Bar is 85%. Persistent failures (survive prompt tuning + schema descriptions): the model

**BREAKTHROUGH (Malin's steer — "can't we parse in the app first?"):** a **deterministic
rule-based parser** (`scripts/askbinge-eval/deterministic.mjs`, `--engine deterministic`)
scores **98.5%** on the gold set — no LLM, no key, no cost — beating every Gemini config.
It nails exactly the fields the LLM failed (decade/excludeSeen/voteAverageMin = 100%).
(98.5% is optimistic on a self-authored gold set — real accuracy is lower; grow the set
with real queries.)

### New architecture: deterministic-first, LLM-fallback
1. **Primary: deterministic parser** → promote `deterministic.mjs` to
   `src/lib/askBinge/parseSearch.ts` (pure, Tier-A, vitest-tested). Handles the
   keyword-driven majority for free + instantly. **This is the gate-passing path.**
2. **Fallback: LLM only for the fuzzy residual** — call an LLM (gemini-2.5-flash, or
   Claude Haiku) ONLY when the parser returns nothing / low confidence (similes, slang,
   novel phrasing). LLM rarely fires → cost stays near zero, long tail covered.
3. The mapping `parseSearch result → TMDB discover params` (section 2 below) is unchanged
   and is the next Tier-A unit. The callable (section 1) is only needed for the fallback.

This supersedes the "LLM-first" framing below — the LLM is now a fallback, not the spine.

## The one sentence

One box where you type *"something funny under 90 min on my services tonight"* and Binge
answers with titles you can actually press play on — filtered to **your** services and
**your** unwatched library, never recommending behind a paywall you don't have.

## Why this is safe + cheap

The LLM **never sees the catalog**. It only translates the sentence → a structured
filter. Retrieval stays free via TMDB + the existing rule engine. So:
- **Cost** is bounded: ~700 in / ~80 out tokens per call on Gemini Flash-Lite ≈ <0.001
  SEK/query, plus 24h cache + global daily ceiling + per-user rate-limit.
- **Risk** is bounded to one thing: translation quality → measured by the eval gate.

## Decision: Gemini Flash-Lite (not Claude Haiku)

The ticket originally proposed Claude Haiku. Switched to **Gemini 2.5 Flash-Lite** —
cheaper per token for a pure structured-extraction task this small, and the structured
`responseSchema` support fits the closed filter schema cleanly. The eval harness is
model-agnostic (`--model` flag), so if Flash-Lite is below bar we can compare
`gemini-2.5-flash` or Haiku with the same gold set before committing.

## Build sequence (after gate passes)

### 1. Cloud Function — `functions/src/askBinge/` (DEPLOY-GATED, Tier D)
Mirror `functions/src/titleRatings/` exactly:
- `onCall({ region: 'europe-west1', secrets: [GEMINI_API_KEY] })`.
- **Global daily ceiling:** `askBingeBudget/{YYYY-MM-DD}.count` transactional increment,
  `DAILY_CAP` ~ 2000 (same pattern as `omdbBudget`).
- **24h query cache:** `askBingeCache/{sha256(normalizedQuery)}` with `checkedAt` epoch
  ms + `isFresh(..., 1 day)`. Normalize = lowercased, trimmed, collapsed whitespace.
- **Per-user rate-limit:** `users/{uid}/askBingeMeta/throttle.lastQueryAt` +
  a rolling daily count (~20/day), `uid` from `request.auth.uid` (never payload). Auth
  required (unlike titleRatings) — it's a per-user spend.
- Call the Generative Language REST endpoint with `SYSTEM_PROMPT` + `RESPONSE_SCHEMA`
  (copy from `scripts/askbinge-eval/schema.mjs` into a shared `functions/src/askBinge/schema.ts`).
- Return the validated filter object. Reject (don't guess) on malformed output.
- Secret provisioning: `firebase functions:secrets:set GEMINI_API_KEY`; deploy via
  `firebase deploy --only functions` (NOT covered by `deploy.yml`).
- Add `export { askBinge } from './askBinge'` to `functions/src/index.ts`.
- `firestore.rules`: `askBingeCache` + `askBingeBudget` are admin-SDK-write only (like
  `omdbBudget`); `users/{uid}/askBingeMeta` is owner-read, admin-write.

### 2. Client filter mapping — `src/lib/askBinge/` (Tier A, pure + tested)
- `askFilterToDiscoverParams(filter, { myProviders })` → the TMDB discover `Record<string,string>`:
  - `genreIds` + `mood`→`MOODS` genre expansion → `with_genres` (pipe-joined).
  - `providerIds` (or `myProvidersOnly` → `user.myProviders`) → `with_watch_providers`.
  - `runtimeMax` → `with_runtime.lte` (**new** — not yet plumbed in discover).
  - `voteAverageMin` → `vote_average.gte`; `decade` → release-date window;
    `originalLanguage` → `with_original_language`; `sortBy` → `sort_by`.
- `excludeSeen` → client-side exclusion Set from `WatchlistContext` (`status==='sedd'`
  + TV `ej_paborjad` logic) ∪ `NotInterestedContext`. TMDB has no exclude-by-id param.
- Unit-test the mapping thoroughly (this is the deterministic half — high coverage here
  means the only fuzzy part left is the LLM, which the eval covers).

### 3. Results surface — `src/components/...` (Tier B, sign-off)
- A search box (likely on `/discover` or a new `/ask`) that calls the `askBinge`
  callable, maps the filter, runs the existing discover/row composition pipeline, and
  renders the existing `RecRow`/card grid. Reuse `dedupeAndExclude` + `applyClientFilters`.
- Show the *interpreted* filter as removable chips ("Komedi · ≤90 min · Mina tjänster")
  so the user sees and can correct the translation — turns a wrong parse into a 1-tap fix.
- Honest empty state when nothing matches on the user's services.

## Acceptance criteria
1. `node scripts/askbinge-eval/run.mjs` reports ≥85% strict on the gold set with the
   chosen model (the gate).
2. `askFilterToDiscoverParams` unit tests cover every dimension incl. mood expansion and
   movie/TV genre variance (28 vs 10759), with `excludeSeen` proven to drop seen ids.
3. The callable enforces all three limits (daily ceiling, 24h cache hit, per-user rate)
   — provable in emulator tests.
4. A query like "rolig film under 90 min på mina tjänster jag inte sett" returns only
   movies ≤90 min on the user's providers, excluding seen titles, with visible filter chips.
