## Principles

### Review process & verification discipline
- **The staged index is ground truth and it is not stable.** Run `git diff` (worktree-vs-index, no `HEAD`) on every reviewed file and confirm EMPTY; end with `git diff --stat` empty + a test run. `git diff HEAD` merges index+worktree and shows an unstaged fix as present (BIN-540: a re-review passed a diff whose INDEX still had the bug). **A re-review's briefed delta is a CLAIM, not a premise** — `git diff <pinned-sha> <current-sha>` every pinned path yourself. BIN-641 r10 was briefed "two files, comment-only"; five blobs had moved and two carried executable changes. Re-derive them; say plainly the premise was false.
- **`git show :<path>` (bare colon = index) is the staged blob.** When worktree and index diverge, test the INDEX (worktree rig below), never the working file. **When NOTHING is staged, `git rev-parse :<path>` returns HEAD's PRE-FIX bytes** — pinning it certifies the opposite of what you reviewed; pin `git hash-object <path>` and say why. Same for a PARTIALLY staged file ("MM"/"AM"): pin and review the index, and NAME the unstaged delta (BIN-596). **A blob-to-blob diff showing a WHOLE-FILE rewrite is usually a line-ending flip, not a rewrite** — the repo has `core.autocrlf=true` and NO `.gitattributes`, so every source blob is LF except any a tool wrote as CRLF; count `\r\n` vs `\n` in `git show :<path>` before reading 250 changed lines (BIN-645's `QuickAddButton.test.tsx` hid a 5-line delta this way and would check out with `\r\r\n`).
- **A concurrent agent shares this tree** — mid-review edits, bytes moved index→worktree, a `git reset` repointing the index, a sibling MUTATION-TESTING the file under review (BIN-641 ×2, BIN-645, BIN-777/646 — mutants those tickets' own tests exist to catch, seen live then self-healed mid-review). So **hash EVERY file a run reads — prod AND test — before and after it**, quote them in the marker, loop `[hash → run → re-hash]` accepting only pre==post==target; re-verify anything Read early against `git show :<path>`. Compare with `git hash-object`/`git rev-parse :<path>`, never a raw `md5sum`. If the worktree copy is mutated when you finish, SAY SO: the index is safe but a later `git add -A` would land the mutant (an UNSTAGED reviewed file gets said loudly — re-add by pathspec). **A failing test NAME absent from the staged blob PROVES a foreign edit**, not a flake — so does a failure on a DIFFERENT invariant than the one under review, and strongest of all an OUTPUT the staged source cannot produce (BIN-815 r2). A sibling's mutant restores between runs, so before/after hashes can BOTH read clean; two distinct mutants inside one 4-second suite run is "continuous churn" — go straight to the isolated worktree. **The cheapest tell that the churn is a SIBLING's mutation run: your mutant kills tests for a case it structurally cannot reach** (BIN-815 r3). Don't reason about the anomaly, `git status` it: `MM` on a file you never edited settles it. Snapshot/restore with `cp` — but `git hash-object` on a path OUTSIDE the worktree skips the autocrlf clean filter, so a scratchpad copy's sha never matches the index sha; compare in-repo paths only, and prefer `git checkout -- <path>` (index, not HEAD, when the file IS staged) to undo a foreign edit.
- **When the churn is CONTINUOUS the hash-loop can't converge — build an isolated worktree of the INDEX and run there:** `git write-tree` → `git commit-tree $TREE -p HEAD -m snap` → `git worktree add --detach <scratch> $COMMIT`, then give it its OWN deps: `npm --prefix <scratch> ci --prefer-offline --no-audit --no-fund` (~50 s from the npm cache). Verify each `git hash-object` == its staged sha, then run the suite AND every mutation there — the shared checkout is untouched. **Never junction `node_modules` into the rig** (the old `mklink /J` recipe): any `rm -rf`/`git worktree remove --force` traverses it and EMPTIES the real `C:\binge\node_modules`, and the scratchpad is SHARED per session, so a sibling agent's cleanup of YOUR worktree does it too (2026-08-01 self-inflicted; 2026-08-08 sibling-inflicted, whole repo left with an empty `node_modules` mid-review). A private install also isolates the vitest cache for free (default `cacheDir` = `node_modules/.vite`; `--cache.dir` is not a vitest 4 flag). Remedy: `npm --prefix /c/binge ci --prefer-offline` (~50 s, verify `ls node_modules/.bin/vitest`) — say so, every commit gate is dead until it is back. Remove the rig with `git worktree remove --force`, or `rm -rf` + `git worktree prune` FROM THE REPO ROOT if it fails `Filename too long`/`Permission denied`. It proves the staged set commits ALONE (typecheck + full suite there); reconcile a differing test count rather than doubting it, and expect FS-walk tests (`design/consistency.test.ts`, 5s timeout) to time out on the slow temp path — environmental, not a diff defect. **Its files check out CRLF** (`core.autocrlf=true`), so an LF-anchored multi-line mutation patch silently no-matches — and `perl -0pi -e` mis-parses `-0pi` besides. Mutate via a script that normalizes `\r\n`, counts occurrences and EXITS NON-ZERO on no-match, and assert the mutant present BEFORE and AFTER the run in the same command. Costs ~4 min end to end; worth it on any auth/data diff. **REUSING the rig across review ROUNDS is how a clean re-review invents a flake:** re-point it (`git checkout --detach $COMMIT`) AND delete its `cacheDir` — a persistent per-run `cacheDir` serves round N−1's mutant. BIN-679 r2 saw 2 of ~30 runs of the CLEAN staged file fail with output byte-identical to a mutant this rig had built (plus one unexplained self-restore inside the worktree); after clearing it, 27/27 green. A "flake" whose failure output equals one of your own mutants is rig contamination — clear, re-run to double-digit greens, and report the bad runs as rig, not as a test defect.
- **Never dismiss on one run a test failing on the exact assertion a fix targets** — but FIRST rule out a foreign edit (hash the file): successive runs failing on DIFFERENT tests is the tell. Then re-run 5-10×, isolated and as invoked. Flake only after double-digit unchanged passes — name it, don't omit the bad run. **Exceptions that DO resolve fast, both cache-shaped: the run(s) right after `rm -rf node_modules/.vite/vitest`** (BIN-687/688, 2 fails on DIFFERENT assertions then 8/8 — cold-cache jitter) and a stale `cacheDir` replaying a prior round's mutant (see the rig bullet); name the cache timing, don't omit the bad runs. **A one-shot worktree-vs-index divergence that self-heals is the same class**: BIN-646's `git diff` showed the staged deletion re-added, then read clean on the next command with `hash-object == :path` — report the sighting, and settle it with an atomic `grep-assert → suite → grep-assert → git status` in ONE command rather than reasoning about it.
- **Markers:** read CONTENTS, never trust freshness. Append naming your own files (don't overwrite a parallel pass's), name any surface no verdict covers, re-stamp per follow-up. **Diff the SIBLING markers' pinned shas against `git rev-parse :<path>` too** — after a round applies fixes they routinely pin bytes that no longer exist (BIN-645 r2: 1 of 13 pins still current), and the un-covered delta is often the round's ONE behavioural change. Say which surfaces their verdicts no longer cover, even when your own verdict passes. Spot-check a marker's EVIDENCE COMMAND, not just its conclusion: BIN-645's security pass closed "consent" on `grep signIn()`, which misses `onClick={signIn}`. A gap it DECLARED may also be closed by bytes newer than its pins. After a SPLIT, sibling OVER-coverage is harmless, but the deferred half owes its own three passes.
- **A mocked Firestore suite is structurally blind to rules bugs** — "only the emulator catches this" needs NEW `npm run test:rules` coverage. `emulators:exec` can fail to start and still exit 0 through a pipe — require a real "Tests N passed".
- **`npm run typecheck` never covers `functions/src`** — run `cd functions && npx tsc --noEmit` separately; root `npm test` DOES run firebase-admin-free `functions/**` tests.
- **A `tasks/*-plan.md`/`todo.md` is a binding spec — including its DELIVERY assumptions**, and the FIRST check is that the staged one describes THIS ticket: BIN-823's commit staged BIN-679's already-shipped plan over HEAD's BIN-815 plan, so the repo's "current plan" doc named a third ticket and a revert would restore a second (`tasks/` is disposable per `code-style.md` — an implemented plan is deleted, never swapped, and never rides a feature commit). Its own audit is not exhaustive: diff its ACCEPTANCE LIST against the shipped mechanism (BIN-505); grep touched field names repo-wide rather than trust its "consumers audited" list; check the STAGED FILE SET against a "two separate commits" line. A criterion answered with "we deliberately did NOT" is UNMET — so is one a LATER decision outgrew, and one whose NAMED EXAMPLE the diff itself rebuts (BIN-641 had both): it reaches her in the report and the plan line gets amended IN PLACE, never silently satisfied and never merely appended to as a dated "review-round fixes" section (BIN-645 did that, leaving the plan specifying a design the ship had dropped). Check EVERY criterion, not just the one a sibling amendment already caught — a self-ticked `[x]` the diff contradicts is the cheapest blocking finding available (BIN-815 r2 ticked "a heartbeat while page collection runs" while 2 of the 3 fetching routes in that phase never start it). Dated reversals may amend a non-high-stakes condition, never Security/DPO/Legal. **A `requiresPlanMode` ticket is not self-certifying**, and re-reviewing an xhigh-driven fix means checking the SPECIFIC condition named — a "deliberately DIFFERENT shape" isn't proof.
- **Verifying a revert / a hand-carved REDUCED diff:** EMPTY `git diff --cached <base> -- <files>` + matching blob hashes proves the restore. Real risk is CROSS-FILE (grep every removed `export`/symbol), STATE ("did it run against prod data?"), and PROSE still asserting the reverted behaviour (incl. a `tasks/todo.md` listing parked work as shipping). A file carrying hunks from BOTH halves must equal HEAD + only the surviving hunk; if the removed half added a NEW MODULE, prove the survivor builds alone on the index worktree.

### Hooks, effects & closure safety
- Hooks run BEFORE any conditional early return — re-verify when a guard lands.
- **A render bail-out must never depend on a lazily-`enabled` query.** A `return null` keyed on `useSeasonRecaps(..., open)`'s data meant the toggle setting `open` never rendered — feature unreachable. Gate on a signal known before opening.
- **Dep arrays must match the query key's granularity** — an effect on a raw object PROP re-fires on a value-equal re-render although React Query (keyed on primitives) did nothing. One Firestore write usually fires onSnapshot twice (optimistic + ack) with fresh identities.
- **The inverse bites harder: a dep the body never READS can be load-bearing, because the callback's IDENTITY is the caller's only signal.** `setRuntime`/`refreshTmdbFields` bail on an empty library while their title-page effects key on nothing watchlist-derived, so on a cold load they last run BEFORE the first snapshot; dropping `items` from those `useCallback` deps no-oped the BIN-93 backfill for a whole visit (BIN-598). Before "cleaning up" a dep, grep each caller's effect deps for a watchlist-derived value; if none, keep `items` (eslint-disable) + a "new identity when a snapshot lands" test.
- **An effect that CONSUMES state must be idempotent, and a single-use read isn't.** `takeNextPath()` (read+remove) in the login redirect effect: `reactStrictMode` is ON by default in Next 16, so run 1 consumes and pushes the remembered path, run 2 reads null and pushes the DEFAULT, which wins. Same shape when a dep takes a second identity while still mounted. Latch with a `useRef` (it survives the remount). Check the value's LIFETIME too — an abandoned sign-in leaves it in `sessionStorage` for the whole tab.
- Optimistic/blur races: mirror the field in a `useRef` set SYNCHRONOUSLY before the `await`, re-sync in an effect, roll back identity-checked — `useOptimisticMirrorField`.
- **A user-facing CONFIRMATION computed from the render closure, beside a write computed from the live ref, can lie.** BIN-641's "omtitt räknad" toast reads `getItem()` while `addItem` reads `itemsRef` after `await fsdb()`: a remote status change/delete in that window makes the toast claim a count that never happened. A `current != null` guard proves a snapshot LANDED, not that the write saw the same row — and it is only null-safety when the shared helper already returns `{}` for `undefined`. Say which direction is reachable (the UI-gated one usually isn't) and whether the residual is cosmetic or data.
- **Sync-ref-before-await fixes same-operation double-fire ONLY**, not cross-operation staleness: a module cache written AFTER an `await` from pre-await data can land after a concurrent mutation's invalidate and re-poison it (`syncProgressToGroups` vs `createGroup`). Ask: "can a DIFFERENT mutation invalidate mid-flight, and does this write compare freshness before landing?" — same for an effect-driven auto-retry beside a re-entrant manual call of that mutation (BIN-587's remedy: pre-await epoch bump + post-read `isCurrent()` + in-flight counter + a once-per-uid latch re-armed on a `uidRef`, never per sign-in).
- **Every session dedupe Set/Map key needs the same discriminants as the `.find` beside it.** Include `uid`; reset on uid change; UN-mark in `catch` and rethrow so a failed commit doesn't opt an id out of a PII migration.
- An eager migration effect deduping only on async listener state re-fires mid-batch — needs the sync ref. Cross-account guard: set `itemsUidRef.current = uid` synchronously in onSnapshot before `setItems`, and gate migration effects on it.
- **Removing an "accidental" error state can break a caller relying on it as a circuit-breaker** — the ghost-member rollback re-armed `GroupPageClient`'s uncapped auto-join into a write-storm.
- **An eager (ungated) fan-out still needs the reference's `isLoading` branch** — dropping it with the `enabled` gate renders a false "hittade inget" mid-fetch; eager fetching overlaps interaction, so the guard matters MORE.
- A `permission-denied` TERMINATES an onSnapshot (no retry) — an opt-in write that flips read access needs an explicit epoch-bump resubscribe. **An `onError` that deliberately leaves `loading: true` is the right DATA call and an incomplete PRODUCT one**: not publishing an empty library as settled truth is correct, but it makes the failure a permanently-spinning app behind a `console.warn`. Require a visible error state + resubscribe, and check the warn TEXT matches what was suspended.

### React Query caching mechanics
- `prefetchQuery` carries the SAME `staleTime` as the consuming `useQuery`; per-title keys stay OUT of `PERSISTED_QUERY_PREFIXES` (5 MB).
- v5: `enabled:false` → `status:'pending'`/`fetchStatus:'idle'`, so `isLoading` is FALSE. `isPending` also settles false on ERROR, so "not yet resolved" is `!isSuccess`. A background refetch error keeps `.data` while flipping status — render-branch order is a second guard. `enabled` does NOT narrow the closure's TS type; default `gcTime` ~5min regardless of `staleTime`; keys stable BY VALUE.

### Firestore rules semantics & atomic commits
- **`get()`/`exists()` in rules NEVER see sibling writes from the same commit** (`writeBatch` and `runTransaction` alike): a doc created in that commit throws `Service call error. Function: [get]` and the WHOLE commit is `PERMISSION_DENIED`. When a diff collapses two awaited writes into one commit, check whether any rule reads a doc written earlier in it. Remedy: sequential writes accepting the orphan window, or a Cloud Function.
- **A range bound is not a state-machine invariant.** `vetoRemaining is int && >=0 && <=1` still permits 0→1; a transition rule must bind against `resource.data` (`req.resource.data.X <= (resource == null ? 1 : resource.data.get('X', 1))`), and the TEST must exercise it. **"Tolerate a corrupt stored value" is half a recovery story**: a client path must SUPPLY the replacement, and its heal predicate must cover EVERY value the rule rejects (`!Number.isInteger(x)` misses an int outside `[0,1]`).
- A merge-write is evaluated against the FULL post-merge doc: a new field joins BOTH the `hasOnly` list and the type chain, or every later write is denied. Client-writable timestamps get `is timestamp && <= request.time` (forge ratchet); optional shape `!('X' in d) || d.X is <type>`; `serverTimestamp()` sentinels and native `Date` both satisfy `is timestamp`.
- Before assuming a "client-only" ship needs rules work, grep `firestore.rules` for the field names. Rules can't count batch siblings — use an Admin-SDK callable.
- **`get()`/`exists()` dedup is per-DOCUMENT rule evaluation, not per list-query request.** "+1 read per request — NOT per item" for a `get()` in a per-item read rule is wrong: a list query evaluates rules per matched doc, so an N-item read costs N extra reads. Flag even when the logic is correct and emulator-tested.

### Firestore doc-ids, indexes & id-scheme migrations
- Same-field WHERE+ORDER never needs a composite; `collectionGroup(kind).orderBy('__name__')` needs no manual index, adding `orderBy(f)` WOULD. A `collectionGroup(name)` sweep matches any future same-named subcollection.
- TMDB movie and TV ids are INDEPENDENT namespaces — collisions are real. Any doc/Map/Set/query key spanning both needs `mediaTypeDocId(mediaType, tmdbId)` or an explicit discriminant.
- **An id-scheme change has THREE call-site classes: readers, the writer's OUTPUT, its read-modify-write SEED input.** `priceHistory` shipped reader fallbacks + a namespaced write but seeded only from the new doc — the first refresh orphaned the series. Grep the collection name, classify EVERY hit.
- A legacy bare-id fallback is acceptable only when the legacy doc's own `mediaType` FIELD matches and the namespaced write always advances so each title self-heals; "deliberately orphan the legacy docs" swallows the first post-deploy write.
- Parse-from-doc-id helpers need a strict `/^(?:0|[1-9][0-9]*)$/` canonical guard (`Number('') === 0` → phantom id 0; `042` ALIASES onto the real `42`) plus an unknown-prefix reject; field-first precedence is `Number.isInteger(f) && f > 0 ? f : parse(docId)`. Client and `functions/src/shared` `mediaTypeDocId.ts` are MIRRORS — diff STAGED blobs, EXCEPT the BIN-618 divergence (only the client rejects aliases: only it reads link-writable swipe ids). **When a mirror diverges, fix all FOUR claim sites** (module header, JSDoc, the sibling test's parity header, any "keep in sync" line) + grep every parser caller for a non-canonical writer. **No absolute about what a BAD id does may ignore the other two resolvers**: the permissive server copy reads the same client-written watchlist docs (six functions call `resolveTmdbId`: availableNotify, insights.rollup, priceDropNotify, streamingOffers, weeklyDigest, followedSeries), and `resolveTmdbId`'s FIELD branch bypasses the doc-id gate whenever the doc carries `tmdbId` — which `buildAddPayload` ALWAYS writes. So a bare "`movie_042` — no reader resolves it back" is false (BIN-646); the honest shape ships in `mediaTypeDocId`'s own JSDoc — read it instead of re-deriving. Since BIN-646 the client field branch canonicalizes a STRING field too, so the ONLY surviving client escape is a NUMERIC `tmdbId: 42` on a `movie_042` doc, which no writer can produce: every writer (`addItem`+`buildAddPayload`, `addToGroupWatchlist`, `notInterested`, `episodeProgress`) feeds doc id and stored field from the SAME value. That absolute is TRUE only with the writer premise attached — re-verify the writer list (grep the collection's `setDoc`s) before passing or failing such a claim.

### Firestore client write-path invariants (incl. freshness stamps)
- Never merge `updatedAt` in a background/denormalization write (`pickContinueWatching` sorts on it) — use a separate stamp; grep who orders by it first.
- Read-repair-on-snapshot needs all THREE `nextAirReadRepair` guards: delta-null termination, the stamp excluded from the diff, a session Set marked SYNCHRONOUSLY pre-await.
- **Never gate a write on the field that write sets, read back through the default `serverTimestamps:'none'`** — the pending sentinel echoes as `null`, the listener re-fires, it writes again. Check what the GATE reads back from.
- **Denormalized parity is on the VALUE expression, not the field name** — a refresher writing raw `movie.title` where `addItem` writes `preferOriginalTitle(...)` reverts every diverging title on first view.
- **A shared freshness stamp bumped by a PARTIAL-field writer launders freshness for fields it never touched** (`nextAirReadRepair` stamping whole-block `tmdbFieldsRefreshedAt`). Stamp only INSIDE the guard writing that sub-group's data; grep the stamp for competing readers.
- **"Omitting is the cheap error" must be proved at the READER's default AND the REPAIR path; it doesn't transfer between sibling stamps** (`addedAt` stamps when in doubt, `watchedAt`/`rewatchCount` say nothing — never "unify" them). **OR-ing a new intent flag into such a guard (`intent || canAutoStampWatchedAt(...)`) disables EVERY property the guard carried**; the half-fix `(intent && current)` closes only the cold load. Gate on the DERIVED outcome (`'rewatchCount' in rewatchFields(...)`), never the raw flag, pinned by a tracked non-'sedd' title with a STORED date asserting neither key lands. A false `tmdbFieldsRefreshedAt` suppresses the self-heal 90 days and the sweep ~6 months. `addedAt`: `toDate()` returns `new Date()` when absent, so a missing value reads as *added just now* forever — `addItem` is its ONLY writer, stamping only when the item is ABSENT from `itemsRef`. `ratedAt` and other derived-recency stamps: `addItem` re-enters, so stamp only on null→value or a change.
- **Checklist for "stop writing defaults, start omitting keys":** `docToItem` defaults them, the rules validator is `hasOnly`, every backend reader guards. Grep the field across `functions/src` + raw `doc.data()` consumers. Collapsing N per-item writes into one bulk `merge:true` is safe only if the key-set matches the old loop.
- **A new CONTEXT-derived `WatchlistItem` field must join `ServerOwned` in `buildAddPayload.ts`**, or `Carryable`/`WatchlistAddPayload` silently admits it as an optional pass-through. `notes` got a type exclusion AND a runtime strip after being bitten once; a field added to `WatchlistItem`/`docToItem` alone (e.g. `addedAtIsFallback`, BIN-601/640) reproduces the hole — unreachable via today's sole builder but a landmine for a future widened signature. Check `buildAddPayload.ts` whenever `WatchlistItem` gains a field.
- **"Pass `current` to protect a re-mark" is dead code when the CTA only renders while `current` is falsy**; a hard-set `status: 'vill_se'` still demotes a terminal `'sedd'` (BIN-593). The defence is the SNAPSHOT-SETTLED gate (`loading` from `useWatchlist()`) as don't-render/`disabled=`/derived-empty list; a handler-only `if (loading) return` leaves an ENABLED dead button (BIN-596). **Split "signed out" from "not ready": key on `uid`, never `user`** — `AuthContext` sets `uid` synchronously and keeps it when the PROFILE read fails, so `!authLoading && !user` reads a signed-IN returning visitor as signed out. A surface that must DECIDE from profile data (LoginPage's onboarding routing) also waits on `profileLoading` — batched true with `uid` in the same `onAuthStateChanged` callback, cleared in `.finally`, so it settles on every path except a hung `ensureUserProfile`. Residual to state, not fix: treating an unloadable profile as `needsOnboarding: false` makes a brand-new account whose profile CREATE failed skip onboarding for good. `QuickRateModal`/`OnboardingFlow`/`settings/import` stay ungated at HEAD (BIN-596 parked) — only a NEW diff touching that branch owns it.
- A new local constant echoing an existing bound (`MY_GROUPS_LIMIT=100` vs rules-enforced `memberUids.size()>100`) imports the authoritative one.

### Status models
- `docToItem`'s `migrateStatus` normalizes TV `'vill_se'`→`'mina'` at READ time, so a downstream TV `'vill_se'` branch is defensively dead, not a bug. Movies have no `'mina'`, load-bearing for `availableNotify`'s skip.
- "Active use" excludes `librarySubState==='avslutad'` but includes `ej_paborjad` and the TV `vill_se` anchor.
- **`watchedAt` survives a status change (BIN-593)** — every reader gates through `seenWatchedAt`/`hasSeenWatchedAt` (`@/lib/watchedAt`); a bare `watchedAt != null` counts re-shelved and abandoned titles as watched, on the PUBLIC profile included.

### GDPR, PII, auth & legal disclosure (bias to keep)
- `users/{uid}` is owner-read-only; every foreign read goes through `getPublicProfileCard(s)` on the `publicProfiles/{uid}` projection. A successful read does NOT imply public — a friend can read a private card, so use `card.isPublic`, never hardcoded `true`. Null = "deleted OR private" → `followFallback`.
- Notes live in owner-only `watchlistNotes`; the notes-null-or-unchanged ratchet lets legacy docs pass unrelated merges while a stale client can't re-leak a NEW note. `addItem` strips `notes`; `updateNotes` omits `updatedAt`.
- Inbound `users/{uid}/followers/*` can NOT be deleted by the account deleter (rules gate on `isOwner(followerUid)`) — tombstones stay, lazy-filtered, reaped by `reclaimOrphanFollows`; retention docs must not claim hard deletion.
- Any new `users/{uid}`/`BingeExport` field needs FOUR sites: `UserProfile` in `domain.ts`, JSON+field table in `docs/data-export-format.md`, `README_TEXT` in `dataExport.ts` (missed twice). A group-scoped opt-in subcollection also moves through `deleteGroup`+`collectDeletionRefs`, `removeMember`, `buildUserExport`, policy docs. Outside `KNOWN_USER_SUBCOLLECTIONS` = explicit wiring.
- A field clamp on a synced profile write must ALSO join `cardSignature` or it freezes at its first value; a material policy change bumps `lastUpdated`.
- **A privacy-policy bullet is reviewed as DATA, not prose.** Check the disclosed value set against the TS union that writes it — `binge:theme` also stores `'system'` (ThemeContext's `ThemeMode`, offered as "System" in `DisplaySection`), so "sparar om du valt ljust eller mörkt" is factually short. A bullet formatted like its exhaustive siblings (`Funktionella cookies … (__cf_bm, __cflb)`) INHERITS their completeness claim even without saying "this is all": say "bl.a." while sibling keys stay undisclosed (`binge:wasLoggedIn`, the React Query persist cache, the plaintext group-invite link, rec-row rotation, the publicProfile signature, plus the two named below). **A category bullet's PROPERTY claims are inherited by the undisclosed remainder exactly like its count** (BIN-795): "ingen tredje part har åtkomst … de lämnar aldrig din enhet" over an admittedly incomplete localStorage list is FALSE for keys the list hasn't reached — the Tillsammans participant id is `generateSecureToken()`d client-side and written to `sessions/{id}/participants/{pid}`, and `binge:fcm:tokenId:{uid}` is a client-generated doc id written to `users/{uid}/fcmTokens`. Scope every promise to the value actually enumerated; a closed, enumerated bullet (the three sessionStorage keys) may keep it. `LegalPageShell`'s `lastUpdated`/`version` are display-only (nothing keys an in-app notice off them; `CURRENT_TERMS_VERSION` in `src/lib/legal.ts` is separate), so editorial → re-stamp `lastUpdated`, leave `version`.
- **EU AI Act Art. 50:** the AI-generated label must be legible NEAR the content. When a refactor turns ONE toggle covering N items into N toggles, a group-level disclosure must MOVE per-item. `DisclosedRecapProse` is the sole emission site. CC BY-SA (ADR-0011): render nothing when `sources.length === 0`.
- Untrusted wiki text: `validateRecapText` is defense-in-depth; the real controls are plain-text rendering (never `dangerouslySetInnerHTML`) and `safeHref` (`^https?://`).
- **Spoiler safety:** the cursor is the CONTIGUOUS-from-start frontier (`contiguousWatchedBoundary`), NEVER `max(watched)`. Prior-season fetch sets derive from `coveredBoundary`, excluding its own season; specials (`season < 1`) excluded at every layer; the fallback walk-back decreases monotonically, capped at `MAX_FALLBACK_STEPS = 3`.
- `ensureUserProfile` wraps its create branch in `runTransaction`, keeping the outer `getDoc` as the returning-user fast path. **That branch stamps `termsAcceptedAt`/`termsVersion`/`ageConfirmedAt` on BROWSE-WRAP consent shown only on `/login`** — a NEW inline `signIn()` elsewhere records a consent + 13+ confirmation never shown. But `TopbarActions` + `HomePageClient`'s landing CTA STILL sign in inline: grep `onClick={signIn}` as well as `signIn()`, or you will certify the consent hole closed while the app's primary CTA still opens it (the footer's Villkor link is not a near-the-button notice, and nothing shows 13+).

### Cloud Functions: notify contracts, sweeps, budgets
- **Per-user error isolation is the house pattern** — `Promise.allSettled` + per-item try/catch, skip-key added BEFORE the try. An unguarded loop lets one failing push abort every later title; a DATE-gated trigger makes the miss PERMANENT.
- **The inbox card is written on the FEATURE opt-in, never gated on `pushEnabled`** — that flag only decides whether FCM fires; coupling them hides the event from everyone without push (default false).
- Dedup is per-USER, not per-title: a `{tmdbId}`-keyed marker skips EVERY owner on a same-day rerun — use `inboxRef.get().exists`. Contract = at-most-once push, exactly-once inbox: marker AFTER content-check+inbox-write; inbox doc = deterministic id + `merge:true`; an empty week never burns it.
- Full-scan pagination: cursor = last doc of the PAGE (never last patched/orphan doc) or the scan wedges; terminate on `snap.empty` OR `snap.size < PAGE_SIZE`. Budget canon: count + `alertedAt`/`capLoggedAt` in ONE transaction, side effects after; MOTN's day key is UTC; a slot is never refunded.
- **Per-chunk rollback must be scoped to "this chunk onward"** — an outer catch assuming nothing committed un-marks committed chunks. Same split in the AUDIT: a VERDICT counter AND a COMMITTED one; one counter makes a mid-page failure contradict its own breakdown. A merge-written audit with an omitted `error` key leaves a prior `error: true` forever.
- `AbortSignal.timeout` covers fetch initiation + headers, NOT `res.json()`'s body. Functions can't import `@/lib/tmdb/providers.ts` — the alias mirrors (`availableNotify/logic.ts`, `insights/rollup.helpers.ts`) must stay in sync with `SWEDISH_PROVIDERS`.

### Design tokens & a11y
- **A bare colour-token name in a className is a silent no-op, not a legacy alias.** `surface` lives under `theme.extend.colors`, so only `bg-`/`text-`/`border-surface` generate. Same for `bg-2`, `rule`, `acc-deep`.
- `<div role="checkbox">` needs `tabIndex={0}`; `role="tooltip" id="X"` needs `aria-describedby`; saffron `:focus-visible` is functional a11y, not a two-accent violation; `role="option"` must be Arrow-key reachable.
- **Moving focus INTO a card that clips needs an INWARD ring.** globals.css draws `:focus-visible` 2px OUTSIDE the border box, so once the focusable element is an inner child of an `overflow: hidden` root (`.ev`, `.prow`, any rounded card) the ring is clipped on three sides. `focus-visible:[outline-offset:-2px]` is the correct fix and it DOES win: Tailwind v3 flattens `@layer` and emits arbitrary/variant utilities LAST, and `.x:focus-visible` (0,2,0) beats bare `:focus-visible` (0,1,0). Prove a new arbitrary utility actually generates — `npx tailwindcss -i src/app/globals.css -o <tmp> --content <file>` + grep — before accepting it; a className-only test pins the string, never the cascade.
- **Un-nesting a control out of a card-wide `<Link>` must hoist ONLY the interactive branch.** Interactive content inside `<a>` is invalid and the `preventDefault`/`stopPropagation` it forces is the tell — but check the ELSE branch: BIN-660 hoisted the non-interactive footer too, so movie cards lost ~27px of navigable surface and flipped `cursor: pointer`→`default`, against the ticket's own "no visual change". A span blockifies as a flex item, so a `block` class "restoring the box model" is a no-op claim. Re-derive spacing against globals.css (a flex `gap` and a child `marginTop` ADD) and scope the compensating value to the TOGGLE BRANCH; the cascade is unpinnable in jsdom but that inline style is not — assert it in BOTH branches.

### Static export, routing & SEO
- Any `src/app/**` page with only static segments pre-renders to `out/**/index.html` — NO `DynamicRouter.tsx` entry, NO rewrite; only `src/app/[...path]/` needs those. With `dynamicParams=false` an unlisted id falls to the SPA catch-all, rendering noindex/NotFound as a **200, not a 404**. `generateMetadata`'s early `return {}` inherits the INDEXABLE root default.
- A sitemap-committed URL must render a 200 `EmptyState` with valid JSON-LD, never `notFound()`. Assert sitemap ↔ `generateStaticParams` equality both ways.
- `usePathname()` returns the real browser path even under the catch-all rewrite but EXCLUDES the query — a "come back where I was" feature keyed on it drops query-only state (`/search/?q=`). Use `location.pathname + location.search` in the click handler (no `useSearchParams`/Suspense cost under `output: 'export'`). Title routes are `/movie/:id/`+`/tv/:id/`, search is `/search/?q=`, recs are `/recommendations/?row=`; a comment or fixture naming `/film/…`, `/sok` or `/rekommendationer/` pins a path the app never produces — `ls src/app` before believing a Swedish-looking route name, and check whether a sibling marker copied it. **Sweep the WHOLE file, not the flagged line: the fix round has twice shipped a NEW invented route while correcting the old one** (BIN-645 fixed `/sok`→`/search` in seven places, introduced `/rekommendationer/` in the added fixture, and left `?next=/film/1399/` standing in the same module's header).
- Build-time fetches: each parallel discover call gets its OWN `withRetry` + inner `.catch(() => [])`; `discover` needs `with_watch_monetization_types` beside `watch_region`; `AbortSignal.timeout(8_000)` per retry ATTEMPT, built inside the retried closure, not the 20s `buildSignal` (5×20s exceeds Next's 60s cap). **A deadline must start when the call DISPATCHES, not when it is created.** `AbortSignal.timeout` runs from creation, `pages.map(p => f(p, {signal: buildSignal()}))` creates all N in one synchronous burst, and `client.ts`'s 8-slot semaphore rejects a QUEUED waiter the moment its signal fires — so only ~`timeout/latency × 8` of the fan-out ever issues a request and `Promise.allSettled` swallows the rest into a green build (measured: 64 of 210 dispatch). The victim is whatever enqueues LAST (BIN-815 emptied every `/person/` URL from the sitemap while `person/[id]` still pre-rendered ~1000 — a sitemap/pre-render mismatch is the "Crawled – not indexed" direction; since BIN-823 both read one manifest and `sitemap.ts` fetches nothing).
- **A kill-switch that disables ONE guard leaves the SECOND guard on the same failure path armed.** `SELECTION_ALLOW_THIN=1` zeroes the coverage floor so a preview may build thin — but a `derive` that TIMES OUT with no previous manifest never reaches `writeSelectionManifest`, so `sitemap.ts`'s `selectionOrThrow` fails that build anyway, from a different file with a different message. Trace a new flag to the END of its failure path, not to the guard it names; a build artifact written only on the success branch is the usual second guard.
- **Build INSTRUMENTATION must emit in the FAILING regime, not just under test:** BIN-815's hang-watchdog started only after a cache MISS, but the Monday full refresh + `REFRESH_AFTER_MS`=6d means a mid-week code deploy does ZERO network fetches — the exact runs that hung — so it would have printed nothing. Name the regime the incident ran in, and enumerate the PHASE from Next's own source: `build/utils.js` runs `buildAppStaticPaths` ONLY when `route.dynamicSegments.length > 0`, so `movie/[id]`+`tv/[id]` `generateStaticParams` run in "Collecting page data" (each with its own INLINED `collectIds` copy no shared helper reaches) while `sitemap.ts` (a metadata route, no dynamic segment) runs in the LATER "Generating static pages". Every worker is a separate PROCESS, so an unregistered route's hang surfaces as a sibling worker's healthy `inflight=0` — partial registration is worse than none. **A phase-scoped inference needs a phase MARKER in the line itself:** the same timer keeps ticking after the phase it was reasoned about (`fetchForBuild` restarts it during export), so `inflight=0` printed while sitemap.ts's ~4000 signal-less list calls hang reads as "not the TMDB layer" and is a lie. Registering a call is behaviour-neutral and SEPARABLE from giving it a signal. Next pipes static-worker stderr to the parent without resetting its hanging-worker SIGTERM timer, so a stderr heartbeat is safe.
- **A "stuck call" threshold set ABOVE the call's own abort deadline can never fire on queue backlog** — `semaphore.ts` rejects a queued waiter the instant its signal fires and the `finally` deregisters it, so with `buildSignal()` at 20s and `STUCK_AFTER_MS` 30s a merely-queued call always leaves the registry first. A STUCK line then means "this outlived its own abort", the instrument's highest-value signal — so a comment justifying the report cap with "1000 queued calls would all read as stuck" (or a `(inkl. köade)` suffix) teaches the next investigator to dismiss exactly that line. Keep the cap, fix the justification. **The same sentence goes false the moment an AGGREGATE is registered under one label**: BIN-815 r4 wrapped `collectPersonIds` (~2100 fetches, no 20 s ceiling of its own) in ONE `trackBuildCall` → `STUCK params:person-ids` every tick on a healthy build. Remedy (r5): opt-in `{aggregate:true}` + its own 4-min threshold (healthy ~40 s, since the inner 20 s signals are created in one burst and the queue self-aborts). Per-call registration inside the pipeline is stronger (no flag to forget); a label-derived threshold is worst (silent string drift). An aggregate entry still feeds `oldest=`, so healthy prints `oldest=40s` with NO STUCK line.
- **`deploy.yml` failure semantics, all three verified:** `timeout-minutes` on a STEP kills only that step and marks it failed — later `if: always()` steps still run; only a JOB-level timeout cancels them (parse the YAML and check `jobs.<id>.timeout-minutes` before believing either). `actions/cache@v4` declares `post-if: success()`, hence `Post Restore … = skipped` on every failed build — that line also PROVES the job kept processing steps, so an explicit `actions/cache/save` with `if: always()` DOES cover the step-timeout case; reject a comment calling that "unverified". `github.run_id` is UNCHANGED across "Re-run jobs", so a per-run cache key needs `run_attempt` too.
- **An inner "soft retreat" timeout only retreats if `timeout + remaining work < the enclosing step cap` — check BOTH branches of a two-value pair against `timeout-minutes`, and price the constant rather than accepting a comment that discloses the gap.** BIN-823 r9 shipped `RESCUE_DERIVE_TIMEOUT_MS` 15 min (inside a 45-min step → retreat completes) beside `REFRESH_DERIVE_TIMEOUT_MS` 150 min (inside 175 → ~25 min left for a 90–120 min render, so the run dies as a step timeout anyway). The disclosure was accurate and the outcome harmless, but the LOWER value strictly dominates: at ~45 min the same pathological run warns, keeps the previous artifact and still deploys, while a healthy derive is single-digit minutes (the file's own `AGGREGATE_STUCK_AFTER_MS` comment calls ~40 s healthy) so nothing real is aborted. Derive the healthy duration from a sibling constant's rationale, then say which value the enclosing cap actually permits — and accept "documented, decided with data on ticket X" when the safe window (55–85 min here) is two single measurements away from the only cold floor (44,5 min); a blind pick between two n=1 numbers is not better than a dated ticket. **A runbook remedy's second half is checked against the REGIME FLAG the remedy's own command sets, not against the artifact it saves.** r10 fixed "re-run it, the work is kept" (true: `if: always()` cache-save survives a step timeout) and shipped a new false tail — "de typer som redan blev klara härleds inte om" — while the command it tells you to re-run is `-f full_refresh=true`, which sets `TMDB_SELECTION_REFRESH=1`, and `mustDerive = refresh || …` re-derives ALL types regardless of manifest freshness. The saved `.tmdb-cache` buys a passing coverage FLOOR (the manifest) and a warm detail cache (`buildCache` entries) — TWO artifacts on one cache key, and the warm cast phase belongs to the SECOND: r11 shipped that clause with "det sparade manifestet" as the subject, copied verbatim from r10's finding text. Write a finding as prose you would accept in the file; a loose attribution in the finding becomes a wrong claim in the repo. Trace the remedy's flag through the code it triggers, every round — r2, r5, r7, r8, r10 and r11 each invented a claim while correcting the previous one. **A MEASUREMENT is scoped to the code path that produced it:** the 2 672 s person derive was measured with a cache-BYPASSING `getMovie` that the SAME commit replaced with `fetchForBuild`, so it still describes an evacuated cache (preview, true cold start) but not the first post-ship push, which restores `.tmdb-cache` via `restore-keys: tmdb-cache-` and reads those ~2 000 cast details warm. Re-scope every quoted number to the regime the NEW code produces before letting prose predict an outcome from it.

### Comment-vs-code corpus
- STALE COMMENT, CORRECT CODE: flag the comment. **A PAST-TENSE claim about how many COPIES a helper had is a claim about a decision record — check it against `git show HEAD:<file>` and against any ADR the same diff amends.** A round that DELETES a call site routinely miscounts a SHARED helper's second caller as a second copy: BIN-823 r4's `sitemap.ts` header called its use of `collectPersonIds` "en fjärde kopia" when ADR 0005 — amended two files away in the same commit to say "EN delad pipeline, inte två kopior" — exists precisely because there was only ever one. But the VAR grep is NOT the enumerator: r6 fixed all four var sites and left the SAME ADR's Fork E ("Sitemapen kastar … i stället för att falla tillbaka") contradicted by the seed-fallback branch added in the same commit — a decision record authored ALONGSIDE the code it documents is self-contradiction, not staleness, and Fork E never names the var. Grep the BEHAVIOUR word (kastar/faller tillbaka) as well as the symbol, and re-read a new ADR against the diff's last hunk. **A CORRECTION is itself a reversal — re-derive every FORMULA, COMPARATOR and mirrored code comment built on the number you just corrected, starting with the paragraph directly BELOW it:** BIN-823 r7 re-anchored "~10 GB/deploy" and left the raise formula, its comparator and two copies in `selectionManifest.ts` on the retired anchor (~45 % understated against a 25 SEK/mån cap). `git grep` the number — then re-read the SENTENCE it was spliced into (r8 left a dangling `En takhöjning till`). A round that "took" a prose finding enumerates only the files IT found (BIN-823 r2 left `buildFetch.ts`'s watchdog rationale naming the now-fetch-free `sitemap.ts` as the later phase's biggest un-instrumented fetcher, and counting three `collectIds` copies after the diff deleted one — `git grep collectIds` finds both; a nav claim inside an instrument's own rationale block misaims the next investigation, which is what that block exists to prevent). **A "same pattern as <module>" cross-reference inherits EVERY property of the module it names, and converges only when SPLIT into shared vs explicitly-NOT-shared** — `canonicalSpecials.ts` burned six rounds on one sentence before landing "shares relatedSeries.ts's SHAPE … but not its affordance (tickable) nor its cost"; READ the named module to price each clause, and scope a "nothing is stored here but numbers" claim to the DATA — that same file checks in 22 TMDB episode titles as comments. **JSDoc orphaning runs BOTH ways** — a new doc above an existing function steals it (BIN-616); a new function/test+doc inserted between a block and what it documents leaves that one bare (BIN-641 ×3, incl. a section BANNER left heading a newly inserted `describe`). **A comment asserting the fix must not survive beside the code that IS the fix** — grep the claim repo-wide and re-read every ASYMMETRY/never-list the diff falsifies, in the SAME diff. **Verify any comment naming an enforcement or UI SURFACE, and SCOPE a premise to the path it holds for** (BIN-641: "counts the same as from Bibliotek's status menu" — `WatchlistPage` renders no `StatusButton`). **Swapping in a new EXAMPLE never converges — restate the caveat as a PROPERTY**: BIN-641 burned four rounds, each concrete claim wrong in turn, closing as "a caller that does not state intent must not count, whether or not it can currently produce the transition". Justify defence-in-depth as self-consistency, never as a live failure. Enumerating callers as a CLASS ("CSV import, onboarding, add-all") stays fine — that claims membership, not reachability. **`// eslint-disable-next-line rule -- reason` covers only the LINE AFTER it** (BIN-598: a wrapped reason suppresses nothing and adds "Unused eslint-disable directive"); directive LAST, then `npx eslint`. ### Testing mechanics
- **A mock with FEWER parameters than the real hook deletes the behaviour under test** — a `useSeasonRecaps` mock dropping the `enabled` arg always returned loaded data. A "simpler" mock is a signal to check what the dropped parameter gates. **A persisted BUILD ARTIFACT read from `process.cwd()` deletes it the same way without touching any test file:** BIN-823 made `generateStaticParams` short-circuit on `.tmdb-cache/selection-*.json`, so the unstaged BIN-815 guard `titleParams.watchdog.test.ts` went 11 green → 10 red the moment a verification build wrote those manifests, and stays green in CI only because `npm test` runs BEFORE the cache-restore step. When a diff adds a cwd-relative cache/artifact, grep the suite for files exercising the reading code without overriding its dir env (`TMDB_CACHE_DIR`) and re-run with the artifact PRESENT — a briefed "full suite green" predating the verification build is stale, not false.
- Prove a guard is load-bearing by driving the exact failure its absence produces, not a "was called" spy. A test NAME claiming a transition it doesn't exercise is false confidence — read the assertion, not the title.
- **Three grades, not two: vacuous (never fails) < IMPLIED (fails, never ALONE) < independent.** A distinctness/totality assertion over the SAME inputs the per-case tests pin is only partial (`new Set(verdicts).size === 3` failed only alongside case 2). Prove the grade by mutation; if none makes it the SOLE failure, say "implied, no added detection power". **A key-set-EQUALITY assertion is only as strong as its fixture** (BIN-641): re-run against a fixture carrying every field the new branch can touch, and prove the repair by leaking a key the payload does NOT already carry. **A conjunct added in RESPONSE to a review needs a fixture that FAILS that conjunct while the flag is true**, or "N tests pin it" is false (BIN-641's toast survived swapping `'rewatchCount' in rewatchFields(...)` for the raw flag). Run the mutant yourself before accepting "tests pin it", and re-run it after a REVIEW-ROUND fix. **Mutate EACH conjunct of an "A and B; removing either fails N tests" criterion separately** — BIN-815 r3 was half true: stripping `trackBuildCall` killed exactly 3 tests per route, but removing the sibling `startBuildWatchdog()` left 6/6 green, because the 1000 `trackBuildCall`s are created in the SAME synchronous burst and the first one starts the timer. A belt-and-braces call placed "before the first fetch" in a body whose fetches are all created synchronously is unreachable-as-a-difference: the code may stay, but the `[mutation-verified]` tick and any "if this is removed, X breaks" comment are then not merely untested, they are UNTRUE — correct the claim, don't add a test that can't exist. **An order-PRESERVING comparator mutant is a no-op, not a surviving guard** — V8's sort is stable and a `Map` iterates in insertion order, so `.sort(() => 0)` over an insertion-ordered registry returns the identical list; only the REVERSED comparator tests an "oldest first" claim. **A round-trip test whose READER re-applies the writer's guard proves nothing about the writer** — BIN-645's "is applied by rememberNextPath" read back through `takeNextPath()`, which strips again, so deleting the write-side `stripUnsafeQuery` left all 29 green; assert the STORED bytes. Sibling trap in the same file: a fixture written AFTER the render can't prove the render didn't consume it (`setItem` then `getItem` only proves storage works). (The "a wait that only STARTS" and per-call-`useRouter`-mock traps are in the always-on `lessons-digest.md` — don't re-derive them here.)
- **A helper's unit test does not discharge an acceptance criterion phrased about the CALLER — and an OPT-IN flag makes the caller the whole risk.** BIN-815 r5 pinned `{aggregate:true}`'s threshold branch in both directions inside `buildFetch.test.ts` (1 and 11 kills), then deleting the flag from `person/[id]/page.tsx`'s sole call site left 2665/2665 green: the false-positive the flag exists to prevent is unpinned exactly where a future edit drops it. Mutate the CALL SITE before accepting a `[mutation-verified]` tick whose criterion is phrased about the build/user ("a healthy build never prints X"). `planQuickRateWrite` was fully unit-tested while nothing forced `QuickRateModal` to obey the verdict — widening its `plan === 'rating-and-status'` to `plan !== 'add-as-seen'` kept the helper suite green and restored BIN-599's rewatch inflation. Remedy: a component test mocking ONLY the boundary modules and asserting on the WRITES, not the verdict. Reproduce that mutation yourself — and when a two-link chain (component → hook → context) has BOTH changed links independently pinned, that composes and DOES discharge it (BIN-641). **A HARDCODED discriminant at the call site is its own unpinned link**: BIN-679's specials row passes a literal `0` to the guarded hook, and flipping it to `1` left 37/37 green because the component test only COUNTED checkboxes and never fired one against a spy. A criterion phrased "ticking X must never write Y" needs a click + `toHaveBeenCalledWith(...)` (pinning arity too), a spy on whatever child turns that literal into a DOC ID, and an UN-tick so `true` isn't hardcoded — with those four, every call-site mutant dies singly (r3, gap closed). **But a spy on a MOCKED child pins the WIRING, never the child's own guard** (r4): the added `expect(call[0].watched).toBe(false)` kills `watched={true}` at `EpisodeRow.tsx`'s sole `EpisodeReactions` call, while neutering `if (!watched)` INSIDE `EpisodeReactions` — the branch the sign-off is actually staked on — leaves 2683/2683 green, because the only file rendering it mocks it away. Say which link a mock-prop assert can and cannot reach, and mutate the INVERSE too: `watched={false}` (gate stuck shut, feature dead) also survived the full suite — assert both directions from the fixture that already renders the watched case. Sibling check when a row DECORATES a domain object for a shared child (`{...episode, name: name+' ('+year+')'}`): grep the child for every sink the mutated field can reach — Firestore write, analytics, React `key`, doc id — before passing it.
- **A test that lets production's build-log output reach the REAL stderr publishes it**: `::warning::` / `::error::` are GitHub Actions annotation syntax, so a suite exercising a code path that writes them annotates every green `npm test` run with fake production alarms (BIN-823: 7 per run from `selectionResolve.test.ts`). The tell is a sibling file in the SAME diff spying `process.stderr.write` and saying why (`selectionParams.test.ts`) — self-inconsistency inside one ticket, one-line fix in the top-level `beforeEach`. ONE shared spy per file: a test that installs a nested second spy over it makes `mockRestore()` ambiguous and its own assertion read the wrong call list.
- Coverage gaps are `binge-test-reviewer`'s gate (advisory here) — flag one when an invariant was verified by manual trace only.

### Domain gotchas & accepted behaviours (don't re-flag)
- Dates: `new Date(iso + 'T00:00:00')` = LOCAL midnight, an established idiom (advisory only). `stockholmDayId` is the canonical day key, never `toISOString().slice(0,10)`. TMDB `release_date` is a CALENDAR date — `slice(0,10)` behind a `length>=10` guard, never a tz conversion; persistent cards use time-neutral copy, only same-day push says "idag".
