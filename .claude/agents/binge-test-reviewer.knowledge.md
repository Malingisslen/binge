## Review protocol & scope discipline
- **Never weaken to go green** — strict→loose, deleted assertion, `.skip`/`.only`, an expectation rewritten to match buggy output: prod code is the suspect. **Pin derived state** (`watchStatus`, `libraryView`, `calendar/summary`, `airingState`, `migrateStatus`). A rules change with no `vitest.rules.config.ts` update (emulator, Java/JBR on PATH) is a gap; `src/lib/design/consistency.test.ts` is never disabled for a lazy change. **A handler→orchestrator split earns a pass only when four things are separately mutation-checked, not read off the file list**: delete a whole sweep/branch and require the failure to NAME the field it broke; flip any `-1`-died-vs-`0`-clean sentinel; break EACH of two sites sharing one ceiling predicate ALONE, other stays green; failed batch-commit still increments the "deleted" counter (BIN-727 `runCleanup.ts`). **Asserting a raw CSS/Tailwind class string is the RIGHT call when the class IS the fix and jsdom cannot compute the effect** (BIN-660) — then **one probe PER TERM, since a term is not covered by a probe on a NEIGHBOURING term**, and **a MODIFIER class does not pin the BASE class it modifies** (use `classList.contains('flex')`). Inline `style` numbers need `toHaveStyle` on the applying case AND `not.toHaveStyle` on the non-applying one. [arkiv 01]
- Read `.claude/rules/accepted-deviations.md` before filing — the pattern may be a decided call. **Absent a formal entry, an untested imperative call site can be judged against codebase PRECEDENT rather than filed as a fresh gap**: grep the same file/loop for an equivalent-risk SIBLING signal shipped untested with no incident (BIN-856), report it precedent-consistent, NAME that sibling, and don't demand extraction unless the sibling is fixed in the same diff. On a signature-widening test update, judge weakening by mutating the NEW composing step and requiring the PRE-EXISTING boundary tests to redden. **A comment-only fix that swaps a retracted claim for a new causal chain needs the chain walked through the files it names, and an asymmetry it describes needs BOTH directions checked for which is pinned** (BIN-879). **When a false COUNTING clause is struck rather than reworded, audit what the strike leaves behind — a definite article is still a tally**: grade a surviving "THE pin" claim by RE-DERIVING the enumeration read-only, not by another edit round. A TRUE claim is never a finding, however much it resembles the one you struck. **Striking an ENUMERATING clause can leave a neighbouring EQUIVALENCE conclusion built on it standing and now false, however grammatical the rewrite reads** — probe it live: `route.test.mjs`'s `gateMatches()` header struck its 3-mechanism list for a 4th (`keyed`, BIN-990) but kept "a patterns-only helper would answer the same", provably false for `.claude/settings.json` (patterns-only: false; real matcher: true). The sibling file's identical strike (`gate-symmetry.test.mjs`) dropped the count instead of a conclusion — that's the fix. [arkiv 02, 62]
- Verify, never inherit, claims — "already mutation-tested", a prior entry's numbers, a comment's "would fail against the old code", a marker promising "N notes below", a coordinator's "I mutation-checked two myself"; a handed-down "red-ALONE, 1 of N" may be an UNDER-count. **A handed-down SUITE COUNT is a claim about the SPEAKER'S machine**: a test coupled to a GITIGNORED build artifact is green in CI and red on a dev box (BIN-823's `.tmdb-cache/selection-*.json`), so any diff adding a persisted artifact owes an explicit temp-dir + regime env per test file. **A new test file can REDDEN the suite with no assertion of its own failing** (added under an owned directory fails `gen-ownership-map.mjs --check`, which `npm test` runs); re-run a suspect failure OUTSIDE the sprint worktree before calling it environmental. **A SOURCE-SCANNING guard test owes one probe PER IDIOM, and its docstring's absolutes are the claim to attack**; when retired for a config-wired AST lint rule (BIN-931), demand ONE fixture OUTSIDE the guard's home directory to pin `eslint.config.mjs`'s `files:` scope. **A self-reported gap is a claim too — mutate it.** A control that never reddens is not a control. **A claimed kill-count for "swap to a date condition" is ambiguous between mutation SHAPES** — a raw-field filter (`watchedAt != null`) vs one routed through an already-gated helper (`seenDate(i) != null`) can kill a different count of the same tests (BIN-1027: 1 vs 2) — reproduce the ticket's own literal shape. **A mutation-count/exit-code claim tied to a DATA FILE the diff regenerates is state-dependent** — re-run against the file state that ships, not pre-regeneration (BIN-852: "exit=0→1" became exit=0; "2 of 54" became 1). **A test harness's own comment can misdescribe its SUITE'S coverage, not production's** — grep the literal override/behaviour the comment names every round it or its fixture is touched, rather than crediting the self-description (BIN-1023, closed same-day once the promised override was built). [arkiv 03, 63]
- **FIRST command of every review**: loop `git rev-parse :<f>` vs `git hash-object <f>` over `git diff --cached --name-only`, and **PRINT the sha for EVERY path, not only the mismatches** — a mover a sibling STAGES advances index and worktree together and is silent under a mismatch-only loop. Any mismatch = split index/worktree; `vitest` reads the WORKTREE, CI the INDEX. Shapes seen live: a one-line fix's COMMENT staged but not the line (BIN-617); a new file showing `A` yet staged EMPTY via intent-to-add (`e69de29`); the FIX in the worktree with the GAP in the INDEX; the INDEX EMPTIED by a sibling's commit; the index reshaped SELECTIVELY (a file LEAVING the index is visible only to plain `git status --porcelain`, not `--cached --name-status`); the INDEX holding still while the WORKTREE moves, carrying NEW production logic. Remedy: name `git add <path>` as the required step, never run it on the coordinator's behalf; pin the shas of the bytes you actually mutation-verified and state the other side's separately; make re-staging BLOCKING, naming every path incl. any untracked test file; and say that `git add` of a mover touching `src/**` puts UNREVIEWED code in the commit. Re-run `git status --porcelain` + `git log --oneline -1` at the END of every review, and re-hash every mutation target before the verdict. **The mover can be a file NO ONE'S list ever named** (BIN-844) — audit the full path list against the ORIGINAL brief at start and end. [arkiv 04]
- **Re-read the shas IMMEDIATELY before writing the marker.** The INDEX moves mid-review (BIN-596/617): diff each mover, re-run every mutation touching the changed lines against the NEW bytes, pin, and SAY so. "An added test can only turn things RED" holds ONLY while the harness is untouched: a MOCK edit rewrites the contract every sibling runs under and can turn a prior RED green. **A new test can rewrite that contract from INSIDE its own body, which no harness diff shows** — `vi.mocked(fn).mockResolvedValue(x)` permanently replaces a `beforeAll` value for every later test (grep `vitest.config.ts` for `mockReset`/`restoreMocks`/`clearMocks` first); ask for `mockResolvedValueOnce`. **A PRODUCTION edit inside the mutated function does the same and is easier to miss, because the test file's blob never moved** — grade the survivor by REACHABILITY and report unreachable-by-construction as "the test's name now claims a property it cannot fail on", not "coverage lost". **For a self-graded "equivalent mutant" on a DUPLICATE side-effecting call the default verdict is the opposite — usually NOT equivalent** (BIN-727's redundant early `await writeMarker()`): build the cheapest assertion the claimed-equivalent difference COULD produce (a call count, an order, a written-twice check) and run it. When they yank the TOOLCHAIN mid-review, don't `npm install` on their behalf — substitute proxy greps and never inherit "typecheck clean, eslint 0 errors". [arkiv 05]
- Behavioral equivalence with pre-diff code is the FLOOR of a refactor review, not the verdict — also ask whether the preserved behavior was itself correct ("faithful to the old call-site literals" once approved a live merge-write data-loss bug). If a guard blocks a mutation, hand-trace and report as static-only — never claim a live result you didn't get, and **never carry a hand-traced EXACT COUNT forward as fact once the emulator is reachable**: BIN-941's port-blocked pass archived a hand-traced row count for a zero-padding-regex mutation that a live re-run contradicted, because one listed row was already denied by the prefix check and can never move with that mutation. The qualitative conclusion survived; the count didn't. Re-run a prior pass's hand-traced number the moment the blocker clears, and correct the archive rather than repeating it. [arkiv 45]
- **"Previously-passed files are byte-identical" is a claim to verify** — diff every gated file vs HEAD (BIN-1028: 4 passed files struck same commit). "Shallow checkout" needs EVERY workflow running it checked for its own `fetch-depth`. [arkiv 55]
- **A "comment says don't shrink this array" mitigation for a list-can-be-silently-shrunk finding is weaker than this repo's own established fix for the identical class, and a same-day precedent overrides a prior LOW-severity call to accept prose** (`docs/org/route.test.mjs`'s `GATE_SCRIPTS` against BIN-838's count floor). **Build it as a FLOOR, not an equality** **and require the no-duplicate companion** `expect(new Set(GATE_SCRIPTS).size).toBe(GATE_SCRIPTS.length)`, proved by the decisive mutation: shrink by one real entry and pad back to N by DUPLICATING an existing one. **A floor DERIVED from the list's own length (`const MIN = REQUIRED.length`) is circular and can never fail alone** — hardcode it. **An EMPTIED array is silent — `it.each([])` registers ZERO tests with no error — so the floor is the ONLY thing between an emptied list and a green suite.** **A count floor over a UNION of sources is blind to one source vanishing when the survivors alone clear it**: demand one membership pin per source. Also owed: grep the whole file AND co-staged paths for other restatements of a corrected claim; RUN a regex a comment describes in nouns; a comment attributing a moved CI step to "workflow file X" needs both files diffed and ranked by `on:` triggers. [arkiv 06]
- **An uncleared mock forces the NEXT test into `.at(-1)`/delta workarounds — judge those as a symptom, not a defect, and check whether `mockClear()` was simply left off.** BIN-844: `signOutMock` was the only mock never cleared in `AuthContext.tsx`'s `beforeEach`, so its call log accumulated file-wide; the workaround was sound but papered over a one-line harness gap. Ask this whenever a test reaches for `.at(-1)`/`mock.calls.length` deltas instead of `toHaveBeenCalledTimes(N)`. Applying the fix can strand its justifying comment in the SAME diff — grep it against the `beforeEach` diff. [arkiv 07]

## Mutation-testing protocol (the house method)
- Per criterion: edit the REAL prod file → run → confirm the expected AND ONLY the expected test fails → restore from a scratchpad backup (`diff -q` it byte-identical) → `git diff` shows only the real work → suite green → next. Never `git stash` mid-review (unstages staged files); never `git checkout --` a file that may hold other uncommitted work. **After restoring, re-check the INDEX, not just the worktree** — something here auto-`git add`s a saved file, so a mutation can transiently land IN THE INDEX while the worktree restore is byte-identical; `git status --porcelain <f>` showing `MM` right after a restore is the tell. **`git hash-object` vs `git rev-parse :<f>` is the FIRST command, before touching anything, because a file can ALREADY be sitting mutated when a review starts** — a backup taken AFTER first observing it captures the CONTAMINATED state, so restoring reproduces the mutant while `diff -q` looks clean; when that first check disagrees, restore from `git checkout -- <path>`, confirm both hashes match, THEN take the backup. **Contamination can arrive MID-review from a concurrent process, and the restore must preserve THEIR bytes**: snapshot the file the moment it differs from what you last wrote, build your own mutant from your own clean snapshot, then restore — to the mover's snapshot if their edit looked like real work, or to `git show :<path>` if it was placeholder debris. [arkiv 08]
- **PROVE the mutation landed before believing a green run.** `src/**` is MIXED — `page.tsx` CRLF, `nextPath.ts` LF — so a multi-line `perl -0pi -e` silently matches nothing and exits 0, and the green suite reads as "no test catches this", manufacturing false gaps. Splice by LINE INDEX preserving each line's own terminator (`text.split(/(?<=\n)/)`, re-attach the matched `\r?\n`); after ANY mutation `grep -n` / echo OLD+NEW. A scripted loop with an unexpanded `$VAR` makes `cp` fail and the next mutation stacks on the previous. `cp`-restore can normalize EOLs — re-check with `git hash-object` vs `git rev-parse :<f>`, not `file`. **`core.autocrlf=true` here**, so blobs are LF while worktrees are CRLF and `git hash-object` applies the clean filter — a worktree/index sha MATCH proves nothing about EOLs. An "EOL-only normalization, content unchanged" claim must be PROVEN, not assumed: strip `\r\n`→`\n` from BOTH blobs in python and diff those (`grep -c $'\r'` on a piped blob is unreliable in Git Bash). [arkiv 46]
- **`rm -rf node_modules/.vite/vitest` before EVERY run in a mutation loop** — the on-disk transform cache serves the PREVIOUS mutation's module after a `cp` restore (BIN-645); tell it from a real flake by the SIGNATURE (each phantom red reproduces a mutation already run this session). **Grep the mutant BEFORE *and* AFTER the test run inside the SAME command** — a concurrent session can restore the file mid-run, fabricating a coverage gap, and the post-run grep is the only guarantee in a sprint worktree, which has no local `node_modules` so the cache-clear is a silent no-op. **The anomaly runs BACKWARDS too — a restored file can RE-ACQUIRE the previous mutant mid-run**; the tell is an IMPOSSIBLE result, so bracket EVERY run with `md5sum` on ALL mutation targets. **Mutate in an ISOLATED worktree built FROM THE INDEX whenever siblings share the checkout** (`git write-tree` → `git commit-tree` → `git worktree add --detach`), with its OWN `node_modules` via `npm ci --prefix <wt>` and **NEVER a `mklink /J` junction back to `C:\binge\node_modules`** (a `git worktree remove --force` follows it and empties the shared toolchain). **A junction makes isolation FAKE unless you also override `cacheDir`**, and **an isolated `cacheDir` is still NOT enough** — `rm -rf <cacheDir>` before EVERY run, mutant and control alike, plus a restore-and-control run after each mutant. [arkiv 09]
- **Never mutate `firestore.rules` in place** — killed mid-edit agents have left it broken, and a concurrent session does mutate the SHARED live file mid-review (an unstaged `/* MUTANT: … */`, or a "Change detected, updating rules… WARNING Unused function" on a run where the function should be referenced; RESTORE FROM BACKUP IMMEDIATELY). Use a scratchpad COPY: mutate the copy and run a COPY of the existing test file with its `readFileSync(...)` repointed at the scratch copy. That copy needs its own emulator + config, since `vitest.rules.config.ts`'s `include: ['src/test/rules/**/*.test.ts']` won't pick up a file outside the glob — drop the repointed test INSIDE `src/test/rules/` under a throwaway untracked name with a distinct `PROJECT_ID`, run it via `firebase -c <scratch>/firebase.json emulators:exec --only firestore --project <distinct-id>` on offset ports (8091/4491/4592). **The plain `npm run test:rules` CONTROL run needs the same offset-port treatment whenever a concurrent session holds 8080** — the firestore emulator does NOT no-op on a taken port, it hard-fails with zero tests run and is easy to mistake for a red suite. `md5sum`/`git status --porcelain` the real `firestore.rules` before AND after EVERY run — control and mutant alike — AND once more immediately before writing the verdict. [arkiv 10]
- Mutate the CALLER performing the side effect, not only the extracted helper — a helper can be immaculate while the Firestore write is unpinned. **A stamp-DECISION composition at a call site is a separate mutation target from the shared derivation the same diff already swept**: BIN-814's `shouldStampProvidersAtAdd` had 8 dedicated tests and zero at its one call site in `WatchlistContext.tsx`'s `addItem`, because the harness's `newTitle()` type `Omit<…|'subscriptionProviders'>` means no fixture can even SUPPLY the field. Also mutate a `useRef` mirror back to the closure state var (BIN-593), every assignment of a shared ref, and duplicated constants. **Mechanical sweep across N sibling mutators** (BIN-598): diff the harness's ref list against the production export list — a function in NEITHER has ZERO coverage — and **a filed sweep-gap does NOT close itself**, so re-run the revert every round. **Count CALL SITES, never files** for a freshly-introduced shared helper (`grep -rn '<newHelperName>' src/**`), requiring at EACH site a fixture where the new helper DISAGREES with the old field plus a null-fallback case. **Testing the HUB and the SUPPLIER does not test the MIDDLE LINK**: a component receiving a prop and handing it to a mocked bare-`vi.fn()` hook without asserting the call's ARGUMENTS is the gap — and the same topology recurs at a whole SHARED MODULE every consumer `vi.mock`s wholesale. [arkiv 11]
- Dual-guard fail-safes (`condA==null || condB==null`): mutate EACH independently — co-occurrence can make one provably dead (BIN-433); a COMPOSITE guard needs one fixture per term, including char-class terms (`code < 0x20 || code === 0x7f` needs a DEL fixture beside the `\n` one, BIN-645). Ditto a `try/catch`-PER-API-METHOD resilience claim: "survives storage unavailable" spying only `Storage.prototype.setItem` left the READER's try/catch deletable, and that reader sits in a `useEffect` where a throw kills the redirect. For ≥2 sequential exclusion guards the fixture must pass every guard EXCEPT the one under test — and when the SAME condition is copied into two sibling effects, the fixture reaching it in one can be stopped by an EARLIER return in the other, so mutate per effect (BIN-816). Severity splits on whether an inner guard covers it: an early-out whose write is refused again downstream is a cost-saving LOW; one whose `users/{uid}/watchlist/*` batch has NO second guard is blocking. A shared guard reused at sites with DIFFERENT sibling guards needs a fixture per site (BIN-509). **A handed-down "N red" for a composite guard is ambiguous between "drop one term" and "drop the whole condition" — mutate term-by-term and report the per-term breakdown** (BIN-849). **A "two shapes, one per AND-term" test needs each fixture to isolate its OWN term by satisfying every OTHER term** (BIN-808). [arkiv 12]
- **A parameter-narrowing guard reachable only via a SINGLE current caller that hardcodes the safe literal mutates clean** — no fixture supplies the OTHER value the function's own type still permits (BIN-954: `updateProgress`'s `else if (opts?.addIfMissing && mediaType === 'tv')`, whose one caller `useEpisodeProgressWithSync.ts` only ever passes `'tv'`). Distinct from a provably-UNREACHABLE defense-in-depth guard (exempt): this one IS reachable through the public signature, just unexercised — report as a non-blocking gap (one fixture with the other value), especially when the mislabeled write would corrupt data. **A comment's ordering claim ("mark the ref AFTER not BEFORE the write, or a concurrent second call would…") is only proven by a test that drives the interleaving it describes** — report it as unverified, not confirmed. [arkiv 13]

## Boundary & threshold completeness
- **A test that DERIVES its fixture size from the constant under test pins the loop and nothing about the constant's own ceiling** — `refs(DELETION_CHUNK + 1)` is right for the chunking but leaves `DELETION_CHUNK = 450` free to become 600 at full green; one line closes it: `expect(DELETION_CHUNK).toBeLessThan(500)`. Mirror shape one layer out: when a diff extracts every pure predicate of a destructive sweep into an admin-free sibling but leaves the blast-radius CEILING inline in the firebase-admin entrypoint, the constant's test degenerates to a range assertion that cannot tell whether the ceiling is enforced at all, nor `>` from `>=` — don't wave that through on the untestable-entrypoint precedent when the file's OWN convention was followed four times and skipped once, on the guard with the largest blast radius. **The built version reproduces the SAME defect one level in — a boundary fixture written as `f(CONST + 1, n)` pins the `>` and leaves the CONST's magnitude free** (BIN-816's `MIN_CEILING`), and the tell is in the diff: the round that added the floor DELETED the only constant-independent fixture. Count how many surviving fixtures name a LITERAL on both sides — one is enough, none is a gap — and ask for a semantic literal case rather than an exact `toBe(5)`, which punishes legitimate tuning. [arkiv 14]
- `>=` vs `>` is the most-repeated regression here — pin the EXACT boundary from both sides: strict `<` → boundary−1/boundary/+1; `>= N` → >N,==N,<N; `used >= cap` → at-cap carries the load; four-sided window → below/at-lower/at-upper/above; `length >= 4` pinned from BELOW with a −1 twin. Staleness predicates: exactly-at-threshold AND one-unit-past, via epoch-ms arithmetic not `setDate` (BIN-183/184). **A grandfathering/epoch cutover written as `parsedDate < epoch` owes its own AT-epoch fixture** (BIN-917); the same class hides in a DATE-STRING `<=` gate (`s.air_date <= airedFrontierDate`, BIN-615) and in a length gate (`bio.length >= MIN_REAL_BIO`). **A SIBLING threshold added alongside an already-tested one inherits none of its coverage** — ask for the exact-N fixture whenever a new `MIN_*`/`*_CAP`/`*_THRESHOLD` const appears. **A test literally named "caps … at CAP" is not evidence the cap enforces anything if its own fixture total never reaches the cap** — prefer mocking the extraction point with an oversized synthetic set. **A freshness gate written as a NEGATED comparison to fail closed on `NaN` still owes the ordinary exact-boundary pair.** **A `Math.max(ABSOLUTE, pct * previous)` floor has two terms and only ONE is live per fixture**: put the relative term ABOVE the absolute one, or pin the OTHER consumer of the same count and SAY which it is. **When a test pins a workflow/config VALUE, ask for a line-anchored `toMatch`.** [arkiv 15]
- Two-condition pure gate: both-true→true; cond1-false→false; cond2-false-at-boundary→false; cond2-false-above→false; null-sentinel→true (BIN-50). Range-gate+transform (`r>=1 && r<=10` then ÷2): below-min, above-max, non-finite, at-min — at-min pins guard AND transform (BIN-340). `Number('')`/`Number('   ')` coerce to `0`, not `NaN` — "present but blank" fallbacks need `Number.isInteger(x) && x>0`; test empty and whitespace-only. Value-set guards get a bad-TYPE case beside the bad-VALUE case. A TTL/cache/rate-limit claim needs an explicit expiry-crossing test (BIN-510). **A classifier mapping a whole RANGE to one outcome except named exceptions (`classifyStatus`: 4xx → 'rejected' except 404/429) needs the exclusion pinned as a SWEPT PROPERTY over the range** — known-code fixtures all survive a mutant reverting the range check to an enumerated list; only a `for (400..500)` property test catches the next unlisted code. **A minimum-length gate driven only by trivially-short fixtures never reaches the threshold's OWN boundary** — add one fixture AT the threshold. [arkiv 16]

## Vacuous / non-discriminating oracles
- **A TRANSIENT render state is invisible to any oracle read at the end, and a single `await act()` collapses it** — the mutant that matters is a flag flipped ON at the start of an async run and OFF again at the end (BIN-816's `setDeletionInProgress(true)` beside `markDeletionStarted`). A per-render recorder (`const flagRenders: boolean[] = []` pushed from the harness component's body, cleared in `beforeEach` AND after any sign-in helper) is necessary but not sufficient, since inside ONE `act()` React batches the run into a single commit. Drive it as **hold → observe → release**: mock the first awaited collaborator to return a promise you control, `await act(async () => { pending = fn(); })`, assert, then `await act(async () => { release(); await pending; })` and assert again — pinning BOTH directions (happy path and the failure `catch`). Non-vacuity of the hold half needs a SECOND assertion proving execution reached the suspension point; without it, "no render carried true" is equally true of a run that never started. [arkiv 17]
- The shape to hunt: an assertion that still passes if the thing it names is deleted. Ask "what plausible alternate implementation flips this?" — none means vacuous, however specific it looks. **For a MARKUP-VALIDITY / a11y fix the structural oracle is the strong one and the behavioural oracle the weak one**: only `expect(link.contains(button)).toBe(false)` catches a re-nested `<button>` inside `<Link>`; the role-based and tag-based containment checks are COMPLEMENTARY, not subsets. **A containment contract has THREE ends, each needing its own line: outside X, inside Y, and IN ORDER** — both containment assertions are order-blind, so ask for `compareDocumentPosition`/`lastElementChild` whenever the acceptance says "no visual change". A strict SUBSET of a sibling proves nothing new: the real test is **can it fail ALONE?**, and **deleting a subset restatement is a legitimate cleanup, not a weakening** (BIN-646) provided the deleted case NEVER fails alone against a restored copy. **A PERIODIC emitter's "keeps reporting" claim is unpinnable by a single-tick oracle**: advance a SECOND interval and COUNT, then mutate the INTERVAL itself. **Each FIELD of a diagnostic log line is its own term.** **A test titled "never writes to X" that declares its own local `X` and never passes it into the function under test is vacuous by construction** — no mutation inside the function can fail that assertion for the right reason; verify by mutating the CALL SITE instead, swapping in the real forbidden argument (BIN-852's `checkBaselineStaleness` "never writes to problems" test reddened only via an unrelated `ReferenceError`, never via its own `deepEqual`). [arkiv 18]
- **Defense-in-depth double validation hides the first guard, once PER VALIDATOR**: when a value is validated on WRITE and re-validated on READ (`rememberNextPath`/`takeNextPath`, BIN-645), any test asserting through the reader passes with the write-side guard deleted. Assert the INTERMEDIATE directly, never the re-cleaned output — same shape for any strip/normalize-then-reparse pair. **Fixing it for validator #1 does not fix #2**: pinning `safeNextPath`'s write half did not stop the next round's read-side `stripUnsafeQuery` leaving the WRITE-side strip deletable at full green, in the test literally named `is applied by rememberNextPath, not just available to it`. So on any diff ADDING a read-side copy of an existing write-side cleaner, re-mutate the write side, and read a name of the form "is applied by X, not just available to it" as a promise to assert X's OUTPUT (`rememberNextPath('/grupper/X?invite=TOKEN'); expect(sessionStorage.getItem(KEY)).toBe('/grupper/X')`). [arkiv 47]
- The converse acquits most mocked-hook component tests: `not.toHaveBeenCalled()` beside a positive `toHaveBeenCalledWith` in the SAME `it`, and a CALL-COUNT beside an ambiguous-text selector (BIN-641). PROVE by deleting the component's whole write path (`void addItem; void updateStatus;`, keep the state call): green = hollow, red = real (BIN-611). Purely-negative tests still need a positive. **A hook-side guard keyed on an ARGUMENT the component supplies is only as good as the caller's literal, and a "the affordance now exists" test (`queryAllByRole('checkbox').length).toBeGreaterThan(0)`) pins none of it** (BIN-679). **Enumerate EVERY prop the new call site hands the REUSED shared row, every ARGUMENT its callback hands BACK, AND the props that row forwards to ITS children — the third list is the one nobody checks** (a `season`/`tmdbId` skew changes `episodeReactionKey(tmdbId, season, ep)` and collides two threads). **A stakeholder condition recorded in a code comment IS an acceptance criterion** — grep staged comments for "reviewed by / godkänd", COUNT THE CLAUSES, mutate the literal each names. **A forwarded BOOLEAN pinned at ONE value is a HALF pin — the SAME-value hardcode is always the survivor.** **One probe per RENDERING of a number, not per number.** [arkiv 19]
- **A test whose NAME lies is rename-and-annotate, not delete.** Shapes: misattributes a bug's origin; describes a MODEL the fix abandoned (BIN-608); two halves assert the same branch; a name claiming two behaviours whose fixture encodes one, or holding the defining input CONSTANT; a name whose fixture exercises only HALF the API it claims (BIN-645); **an `it.each` whose `$prop` title placeholders never interpolate because the object keys are non-ASCII** — vitest's `\w`-based substitution regex collapses all N rows to ONE name; remedy is ASCII keys. **Always read an `it.each` file's verbose names once.** **A name LISTING several sibling functions as "the same for X, Y and Z" whose body calls only X** needs one fixture PER NAMED function (BIN-596). **A NEGATIVE clause ("only a re-subscribe clears it, NOT a later snapshot") must DELIVER the denied event** between trigger and assertion (BIN-601). ## Fixture-ordering discipline & filter→sort→slice pipelines
- Build fixtures so the WRONG implementation would win: first-wins candidate FIRST, true winner second for argmax; later/heavier value first for earliest-of-N; ascending input for a descending sort; NaN entry AFTER the valid max. Assert the winner's id AND the surviving subset, not just count. `.sort(localeCompare(...,'sv'))`: Set-insertion order must DIFFER from alphabetical (BIN-44). Ordering doesn't reach a lookup that PARTITIONS by key — prove inert with a reorder probe, don't file it (BIN-608). **A "report the N OLDEST + a count" reporter needs THREE probes, and the fixture must break every correlation it can**: reversing the comparator is red-alone, deleting the sort is inert BY CONSTRUCTION when a `Map` keyed by an incrementing token already iterates in ascending order (report equivalence, not a gap), while sorting by the WRONG KEY (`a.label.localeCompare(b.label)`) is a real regression the fixture hides because its labels ascend with age — name the fixture entries so alphabetical order CONTRADICTS age order. [arkiv 29]
- Collision-prevention migration (`mediaTypeDocId`): distinct keys per type in every fixture = green while never exercising the collision — one fixture must seed BOTH types at the SAME raw key, asserting the untouched one survives (BIN-560).
- **Legacy→namespaced read-path fallback over a doc holding a MULTI-WRITER map** (`swipes.votes`, BIN-569/608): a doc-level `byKey.get(k)?.votes ?? legacy.get(id)?.votes` lets the first post-cutover write shadow everyone else's votes. ## Sentinel / key-absence assertions & merge-write payloads
- **Firestore `merge: true`: explicit `null` DELETES stored data; an ABSENT key PRESERVES it.** "Fill every field with a default" in a payload builder is almost always wrong at a merge boundary. Every helper feeding a merge write needs an omission-vs-null test per field; ask not "does this match the old code" but "was the old null/omit choice ever correct" (buildAddPayload shipped live data loss under a "faithful refactor").
- **A new intent term OR-ed in FRONT of a data-loss guard silently disables ALL that guard's other protections while its comment keeps claiming them.** Shape `A && (newIntent || existingStrictGate)`: BIN-641's `opts?.countsAsViewing ||` before `canAutoStampWatchedAt(...)` let a COLD LOAD stomp user-authored `watchedAt`. Mutating the new term both ways proves nothing — **re-run the EXISTING guard's own fixtures with the new flag true.** Unreachable-today is no excuse on a PUBLIC context API. A count half and a value-overwriting half are TWO features — full-revert-probe each (drop / force TRUE / force FALSE / raw-flag form), each reddening a DIFFERENT named case. **Each successive NARROWING is a NEW untested branch the prior round's mutations do not reach**: mutate the NEW gate back to the PREVIOUS one, not just to `true`/`false`/deleted. If green it owes a fixture where the two DIVERGE (a TRACKED NON-'sedd' title) that also SEEDS the protected field (`watchedAt: 2019-04-02` on a `vill_se` doc), else both gates stamp and it is green for the wrong reason. A subset assertion is fine INSIDE an `it` whose other assertion discriminates; the subset rule bites only when the WHOLE test is the subset. [arkiv 50]
- **Sibling stamps with ASYMMETRIC guards** (`addedAt` on `current` alone; `tmdbFieldsRefreshedAt` on `settled && !current`) need a fixture where the guards DISAGREE (cold load, no `current`) — an all-settled fixture proves only the shared half. A predicate with TWO structurally-different TRUE branches needs a fixture per BRANCH (BIN-595). **A THIRD state added later** (BIN-601's `listenerFailedRef`) needs its own fixture diverging on the IDENTICAL empty-items state; its THIRD write site — the per-uid RESET in the subscribe effect — needs an account SWITCH fixture (`rerender` with `authState.uid` moved to `u2`).
- **A ref mirroring state purely so an ASYNC CONTINUATION can see it** (BIN-617) is unpinned by every ORDERED fixture: land the sign-out BETWEEN the call's start and its settlement — deferred rejection, fire `authCallback(null)`, then settle. Pair with the per-tab cap: mutate the guard to `false`, `>=`→`>`, and the per-uid `Map` key to one shared key — all three flip once a SECOND account is appended. A counter incremented only inside `.catch` needs the SUPERSEDED outcome to separate count-on-attempt from count-on-failure.
- Conditionally-omitted fields: assert `'watchedAt' in result === false`, not a value check — catches wrong value AND spurious insertion (BIN-35/91); per conditional field, one written case + one `'key' in update === false` case (BIN-319). Recurring security/cost class: assert a payload does NOT contain `updatedAt` or a PII field. Two optional inputs → two DISTINCT sentinels. Allowlist/prune helpers: assert ABSENCE of a dropped field the fixture actually sets — value-checks on kept fields miss a spread-instead-of-allowlist regression (BIN-423); `toBe` for a pass-through.
- A per-group re-model pins BOTH this group's exact key set AND `not.toHaveProperty` on a sibling's (BIN-468). A field's null-on-other-status value can be an IMPLICIT status filter for readers — a merge write flipping it to omit-preserves needs those readers grepped for a now-needed `status===X` gate (BIN-593/598 `seenWatchedAt`); a consumer that stays green under that helper's mutation is equivalent-by-construction or untested — say which. [arkiv 60]

Source-scan blind spots to name: a chained-call regex misses a VARIABLE-BOUND ref; `[^;\n]` misses a chain broken across lines; a single-quoted literal misses `db.collection("streamingOffers")` — build every scan from one shared quote-agnostic fragment. **A comment/string blanker that treats a template literal as ONE opaque span blanks its `${…}` interpolations too, which are executable code** — an `await`-detecting guard (BIN-1060) is blind to a real `await` inside `` `${await x()}` ``, proven via the guard's own `firstAwaitIndex`. Non-blocking while no such interpolation exists; require the docstring to say so the day one is added. [arkiv 35, 63]
- Mock only the documented choke point: `vi.mock(path, async (importOriginal) => ({ ...(await importOriginal()), oneFn: spy }))` — full-replacement mocks make assertions tautological (BIN-164). **A diff routing a previously-raw fetch through a DISK-CACHE helper (`fetchForBuild`) makes the suite read AND write the repo's real gitignored cache, so a verdict becomes machine-dependent — a passthrough spread-mock is the RIGHT fix and it is checkable**: remove the mock, point `TMDB_CACHE_DIR` at a dir holding the cached payload, and watch the "returns [] when all fetches reject" case FAIL; then scan `.tmdb-cache/` for fixture-shaped entries and name the `rm`. **Mock/fixture arity must track the real API**: `onSnapshot(ref, successCb)` omitting `errorCb` misrepresents the SDK (BIN-596/601); diff the mock's FIELD list against the real one, not just params (BIN-645). **Full-module `vi.mock('@/lib/x')` is fine for testing the CALLER's orchestration, but grep for a sibling `x.test.ts`** — if none exists and it fully replaces the module, the real file's contract has zero direct coverage anywhere (BIN-657/669). **A `writeBatch().commit()` mock hardcoded to always resolve makes "mark the dedup ref before the write, not after a successful commit" structurally unverifiable** — give `writeBatch()` a `commit: vi.fn()` the test can REJECT (BIN-601/640). [arkiv 36]
- **Narrowing a shared write-guard from THROW-always to swallow-one-code-and-RESOLVE(outcome) changes the confirmation contract for every EXTERNAL caller that inferred success from "the await didn't throw", not just the guard's own tests.** BIN-942: `guardedItemWrite` in `WatchlistContext.tsx` narrowed six writers to resolve `'written'|'refused'`, and two callers OUTSIDE the context — `VillSePickerPage`'s toast and `QuickRateModal`'s `setRated` retirement — would have confirmed a write Firestore refused. Grep every caller of a function whose error-handling narrows this way for a confirmation action (toast, `setState` retiring a UI row, analytics) running unconditionally after the `await`, and require it to gate on the RESOLVED discriminant. Closing check: a matrix `it.each` with one row per guarded call site and three assertions per row — refusal resolves `'refused'` AND is reported, any OTHER error still rejects, a landing write resolves `'written'` — plus each external caller's OWN before/after render assertion, since a mocked mutator proves the CALL happened but not that the caller read its return value. [arkiv 37]

## Firestore rules testing
- Verify `assertFails` cases actually threw `PERMISSION_DENIED` in emulator logs (`--reporter=verbose`) — a silently-vacuous assertFails is indistinguishable from a real deny. Rules value-checks get live-mutation-verified on a scratchpad COPY. Firestore's create-vs-update branch is decided PURELY by `resource == null` at eval time, so a seed-delete-repeat test proves nothing an existing `it.each` row already pins for the same id. **A count in a rules-test comment that names "this collection" while counting only "this FILE"'s writers undercounts by whatever lives in a sibling file** (BIN-942: `nextAirReadRepair.ts`'s `flushNextAirWrites`) — grep every file writing `merge: true` into the SAME collection path, and strike such a sentence rather than re-count it. **When a create-narrowing diff adds a POSITIVE boundary control, prove the mutant it names is the one it kills WITHOUT touching the tree** (a read-only `node -e` probe of the old/new/slipped regexes over the block's fixture list), and check each file's `initializeTestEnvironment` argument — a suite booting an inline `OPEN_RULES` string is structurally blind to a rules mutant. **A rules regex is quoted VERBATIM in `docs/workflow-map.html`**, which `scripts/check-workflow-map.mjs` cannot see — grep the map for any literal the diff changes and require the map's OWN follow-up commit, never bundled with the rules commit. **A strike is only terminal if the claim did not MIGRATE into the neighbouring sentence.** [arkiv 38]
- **A Cloud Function writing a NEW field onto a `hasOnly()`-gated, client-writable doc needs a SAME-COMMIT rules-whitelist update** — merge-writes evaluate the FULL post-merge doc, so Admin-SDK bypass protects only itself, not the doc's next client write. Shape: seed a post-writer doc, assert an unrelated client write still succeeds (BIN-402).
- Forge-pin idiom: check the REQUEST doc's key presence — `!('f' in request.resource.data) || request.resource.data.f == resource.data.get('f', null)`. The stored-doc idiom (`!('f' in resource.data)`) is forgeable on any doc created before the field existed (BIN-365). An idiom fix across N OR-branches needs a per-branch deny test.
- Attribution: seed every OTHER whitelist condition correctly so a denial is attributable to the guard under test (BIN-24); seed the owner profile for identity-forgery denies so it isn't a null short-circuit. Multi-branch `allow update`: pair every deny with a positive twin, seed preconditions EXCLUSIVELY so only the target branch is passable, walk every branch (BIN-276).
- Field OMISSION is distinct from wrong-TYPE — implicit fail-closed via `hasOnly()` needs its own test; a shared "valid" positive fixture must INCLUDE every type-guarded field; new stamped fields get the type-reject + future-date-reject pair. `getAfter()`-dependent rules need `writeBatch`, never bare `setDoc` (BIN-25). Size caps: 99→100 allowed + 100→101 denied. Public-read/no-write: anon read succeeds after a disabled-rules seed; both writes fail (BIN-180).
- No-public-read proof: flip the owner's `isPublic` to true mid-test and re-assert the deny (BIN-164). A flipped `assertFails`→`assertSucceeds` is legit when the rule genuinely split, traced against the new rule text. **GDPR export/deletion must never depend on LIST permission for own-doc access** (BIN-184).
- **A denormalized per-item field can go stale vs its profile source of truth** when the cascade write stamping it dies partway. Do NOT prescribe the fail-closed profile `get()` any more: Malin CANCELED BIN-609 on 2026-07-30 (per-read cross-doc cost vs the 25 SEK cap) and `accepted-deviations.md` now forbids re-filing "the visibility read rule fails open" — the accepted mitigation is BIN-587's pending-flag + retry. With a per-item override (BIN-595), pin only that the profile gate can NARROW access. **Firestore subcollections SURVIVE parent-doc deletion** — seed and assert every one (BIN-347). `collectionGroup` queries need an explicit path-shape scope guard.
- A rules test hand-building a batched write proves the RULE denies it, not that the fn stays un-batched — pair with a unit assert it never calls `writeBatch`/`commit` (BIN-556).
- No rules-test update is owed when `git status` shows no `firestore.rules` change and a grep of the changed collection against the rules diff shows zero overlap. A comment asserting a rules-safety OR a REACHABILITY claim gets verified against the actual predicates, never trusted, and **re-verified every round it is rewritten, including a claim stated as a PROPERTY** — re-grep the LIST each round, it changes (BIN-641 burned four rounds). **A create-only doc-id shape guard mirrored onto a SECOND collection** forces a mass rename of every fixture built from the old bare-numeric id — audit it as a potential weakening, not a free pass: renamed fixtures' assertions must be about something OTHER than doc-id shape, a bare-shape fixture must still prove `update` stays grandfathered, and the two collections' alias tables must stay text-identical. [arkiv 39, full BIN-766 trace]

## GDPR, PII, deletion & money guards
- Deletion-cascade correctness is proven by RUNNING the emulator rules suite, not by tracing refs into the delete batch. A compile-time field-coverage gate is classification ONLY; pair with skip-set pinning (BIN-328). Greps prove PRESENCE, not deletion reachability. New user-owned subcollections flow through `KNOWN_USER_SUBCOLLECTIONS`. A destructure-before-write strip needs a key-absence assertion (BIN-505). Cross-check a shipped schema/listener against its binding review-panel plan doc — tests get "deliberately extended" to legitimize a vetoed design. **"Point of no return" ordering (a device-local cleanup that must run AFTER the irreversible server-side delete) needs its own `invocationCallOrder` assertion PER sibling call, not one for the pair** — BIN-844's `clearLocalPushTokenId(id)` had none, so moving it before `await deleteUser(...)` survived the whole file. [arkiv 40]
- Money/catalog: never hardcode a live catalog-derived price — compute it from the lookup at assertion time (recurring BIN-403). Alias-map mirrors (functions vs src): derive expected from the single source of truth, mutation-test BOTH drift directions (BIN-420). Resilience claims get checked at CALL SITES (BIN-430/442). A test hardcoding an unexported const must NAME it in a comment. **A test hand-typing an EXPORTED constant's literal instead of importing it is a DRY nit, not a coverage gap — check the FAILURE MODE (a `startsWith`/prefix matcher still reddens on a future constant edit) before filing it as blocking, not merely a follow-up** (BIN-1038). [arkiv 58]

## Legitimate update vs cover-up
- Legit: the diff visibly implements the new contract, assertions stay strict, no unrelated assertion touched (BIN-16/17). **A strict→REGEX relaxation is an honest environment accommodation, not a weakening, only when THREE things hold and you PROVED the first**: the framework really does normalize the value (probe it — swap the exact form back in and READ the `Received:` line), the exact string is still pinned in the producing helper's own test (`src/lib/calendar/entry.test.ts`), and the component consumes that helper VERBATIM. Strict→different is legit only when production changed FIRST for a real reason (BIN-360/601). **A test rewritten to assert the OPPOSITE needs four things, all checkable in one mutation pass**: the reversal is equally strict, not looser; a NEW case accompanies it so the file GROWS; it is red against the OLD behaviour re-applied; and the ban's stated REASON is genuinely dead, verified in code and not from the diff's own comment — grep for OTHER live paths to the banned state before crediting an "unreachable dead code" claim (BIN-679). Cascade row: every full-array `.toEqual` must GROW — shrinking is the cover-up signal (BIN-175). Retiring a fn: old export gone EVERYWHERE (BIN-178); dropping assertions for a schema-removed field is correct (BIN-292). A `deleteDoc` bump 1→2 is legit when BOTH exact paths are pinned; guard+migration ship atomically (BIN-356). [arkiv 41]
- **Reverts get their own protocol, not mutation-testing:** blob-hash the index against the revert target; diff exported-symbol lists; test-count delta must equal the removed prod tests. Zero-test code reverted removes zero coverage. **In-batch revert** (undone pre-commit) leaves no trace in `git diff --cached`; confirm via `git show HEAD:<path>` and mutate the REJECTED design back in (BIN-593).

## When NO new test is owed
- One-line non-branching discriminants in hooks (`!snap.exists()→'ghost'`, bare `catch→null`) over a tested pure helper (BIN-21); prop-threading, conditional JSX, ARIA spreads, Set toggles (BIN-42); `useMemo`-only optimizations, zero-logic components (BIN-336); a JSDoc MOVED to the fn it describes or CORRECTED to drop a symmetry the code lost (BIN-616/618) — verify by running both copies. Byte-identical delegation to a tested helper (incl. a filter clause inert because a downstream `continue` already dropped it — READ that fn); a signature change threading its new param; pure I/O consolidation over a tested decision fn (BIN-541). Forward-prep with no reachable path; a defense-in-depth guard on a provably unreachable condition — don't demand a first RTL harness over one boolean loading-gate (BIN-596/595/601). **A "belt-and-braces, the real gate is elsewhere" defence must be checked PER SITE by NAMING the module that re-reads the underlying source, because two guards of the same shape in the same file can have opposite verdicts** — BIN-816: true for one early-out (re-reads the marker and refuses), FALSE for a sibling whose write path has no chokepoint. **A HARNESS hardening is the same class — hygiene, unpinnable, file nothing either way**: the honest report is "correct, strictly more robust, not mutation-detectable today", with the mutation you ran to say so. [arkiv 42]
- When such a gate DOES get an RTL harness (BIN-596/645), mutate each layer separately — `current = notReady ? null : getItem(...)`, `disabled={notReady}`, each handler early-return, the refusal toast, the signed-out route (removed AND wrong path), BOTH terms of the auth gate. Mirror fixtures into BOTH siblings (QuickAddButton + StatusButton). The signed-out test must assert three things together — route taken, remembered return path (exact string, `.search` included), and the OLD consent-bypassing `signIn()` NOT called — and keying `signedOut` on the Firestore profile instead of `uid` must go red. Once `disabled={authLoading}` lands, BOTH in-handler auth guards are unreachable — don't call either load-bearing, and don't file the green mutation. **"Exact string, `.search` included" must be checked PER SIBLING, not once per pattern**: BIN-668 copied the same `rememberNextPath(window.location.pathname + window.location.search)` handler into TopbarActions AND HomePageClient, but only TopbarActions' fixture set a query, so dropping `+ window.location.search` in the other stayed green. Flag it, don't block, and re-check the moment `/` grows a query-driven view state. [arkiv 52]
- **Mocking the provider hooks pins the COMPONENT and leaves the PROVIDER's state machine unasserted** — `vi.mock('@/hooks/useWatchlist')` full-replacement is fine for exactly that scope, no more. Mutate the provider facts the component tests assume: `useState(true)` for `loading` → `false`, and any "deliberately stays true" branch (BIN-601's onSnapshot error handler) → `setLoading(false)`. Owed: `loading` assertions in the file rendering the REAL provider — true before the first snapshot, false after, false for a null uid, still true after an error callback. **A DERIVED boolean the provider exposes (`libraryKnown = snapshotSettled && !listenerFailed`) must be mocked as a GETTER computed from the same two primitives, never a settable literal** — a literal lets a test hand the component a combination production cannot produce, silently voiding every gate assertion in the file; grep-diff the mock's formula against `WatchlistContext.tsx`'s own derivation. Confirm reachability, not just the formula match: each of the 4 boolean combinations must be independently producible by the real onSnapshot callbacks — the easy-to-miss cell is "listener fails before ever settling". [arkiv 43]
- **Two exceptions override the exemption above:** (1) the ticket lists a test as an acceptance criterion — an unmet self-imposed bar is a gap even in an exempt shape; extracting the buried decision (BIN-599 → BIN-611's `planQuickRateWrite`) is only HALF the remedy, since the helper's verdict is inert until the CALLER is pinned obeying it. (2) the gate protects a counter/date the code calls permanent-and-uneditable (`rewatchCount`, `watchedAt`) — earns a test at one-boolean size; reserve the exemption for gates whose failure is a redundant render, not silent corruption.

## Rounding, jsdom, TZ/DST
- Rounding oracles need `.5`-exact fixtures (`79/2=39.5`: round=40 vs floor=39) (BIN-87); `Math.round(x*2)/2` with only an `x>0` guard snaps 0.25 to 0 — probe `0.1`. jsdom `getBoundingClientRect()` is always a zero DOMRect. **A "both directions plus the inclusive boundary" claim about a strict inequality (`a > b`) names TWO DIFFERENT mutants, not one — verify each separately.** Reversing the operator (`>`→`<`) tests DIRECTION and is silent exactly AT equality, so it cannot be what pins an "boundary is inclusive" fixture; only widening it to include equality (`>`→`>=`) does. BIN-918's `check_events.mjs` freshness gate (`commitDate > row.ts` ⇒ violation) is the worked example. Both mutants are realistic, so both are owed — and a reviewer who runs only the direction-flip and finds the boundary fixture unreddened should try `>=`/`<=` before concluding the boundary claim is unpinned. [arkiv 53]
- **`fireEvent.click` on a `disabled` button fires NO handler**, so adding `disabled={cond}` RETROACTIVELY hollows out an existing case's post-click assertions: a mutation that used to go red goes green. Verified twice (BIN-645). So on any diff adding `disabled`/`aria-disabled`, RE-RUN the prior round's handler mutations rather than carrying the verdict. Usually NOT a gap: the in-handler guards become unreachable behind an attribute the same case pins (`toBeDisabled()` goes red if removed) — accepted defense-in-depth — but the comments must stop claiming to prove handler behaviour.
- A DST guard is real only if the buggy fixed-ms path yields a DIFFERENT calendar date at that fixture — spring-forward never crosses local midnight (tautologically green), so anchor across FALL-BACK (Sun 2026-10-25) and assert the exact ISO under `TZ=Europe/Stockholm`. Floor BOTH sides to local midnight for whole-day diffs (BIN-145); pick an instant where zones disagree (23:30 UTC = next day CEST) (BIN-105/350).

## Parsers, regex, dispatch, lookup tables & SEO
- `\d+` parsers: test the syntactically-valid-but-semantically-invalid boundary (`/movie/0` → null); strict-digit hardening needs empty-string and phantom-id-0 cases (BIN-560). Regex tightening: a NEGATIVE + POSITIVE pair per pattern — negative-only passes even if the regex reverts (BIN-176); anti-over-rejection tests are as load-bearing as the reject side. `\b` after a hyphenated token false-matches `accent-soft` — use lookarounds. **A "requires a non-empty value" character class (`\S` right after a delimiter) is its own boundary and needs a BARE-KEY fixture, not just a different-value fixture** — `check-public-env.mjs`'s `readAssignedVars` matches `/^\s*(NAME):\s*\S/` so a bare `NEXT_PUBLIC_X:` doesn't count as "assigned", yet every fixture gives the key SOME value, so dropping the trailing `\S` survives. LOW when the bare form is an unrealistic paste, but ask for the fixture whenever a "present vs blank" regex ships a `\S`/`\S+` tail. [arkiv 54]
- Ordered dispatch: the ordering test uses a path matching an early branch correctly, a later one incorrectly (BIN-345). `as Record<string, any>` trips `no-explicit-any` — cast the narrowest slice; `npx eslint` new test files.
- Alias tables: one exhaustive identity loop (every entry × every alias) covers current AND future aliases (BIN-64/90). An ALLOWLIST needs a fixture per MEMBER, not just per rejected value: BIN-645's `RETURN_QUERY_KEYS` was reject-side pinned (adding `'invite'` → red) yet DELETING `'row'` left 25/25 green while killing that surface's return path. Name every member in the keeps-it case; one added `expect` makes the deletion red-alone — re-derive PER MEMBER, not once (`q` reddens 2 cases, `status`/`provider`/`row` 1 each).
- **A URL/route fixture is a factual claim: grep it back to the line that BUILDS it.** Plausible-looking invented routes recurred EIGHT times across BIN-640/645, once inside the fix for the previous one. Check three things per fixture — the route directory exists under `src/app/`, the query KEY is read by that page, and the query VALUE is one the app can actually produce. A fixture naming a surface the app never had keeps passing after that surface moves, so it pins nothing. Curated domain id lists get cross-checked against external ground truth AND the enums/label maps they derive from. Sitemap: two-sided enumeration with REAL constants + an auth/noindex-leak scan (BIN-337/305). **Same discipline for a rejected-Error fixture feeding a message-sniffing branch: grep the fixture's string back to the line that THROWS it, not the constant's declaration** — BIN-777's thrower emits both codes in one message, so a narrow-code fixture is reachable under either branch order; rebuild it as the literal thrown string. **Same discipline for a cross-file `toContain(bareValue)` guard pinning a shared renamed constant: the bare value also matches an unrelated COMMENT mentioning it — anchor on the full declaration (`` `const NAME = '${VALUE}';` ``), never the value alone** — BIN-790's v1 matched `freshness.mjs`'s header comment and survived a rename 20/20 green; v2 reddened alone. The exact-syntax anchor is brittle to a pure reformat — that's the SAFE direction, a DRY nit (BIN-1038), not blocking. [arkiv 44, 61]
