## Review protocol & scope discipline
- Verify, never inherit, claims — "already mutation-tested", a prior entry's numbers, a comment's "would fail against the old code", a marker promising "N notes below", a coordinator's "I mutation-checked two myself"; a handed-down "red-ALONE, 1 of N" may be an UNDER-count.
- **A self-reported gap is a claim too — mutate it.** A control that never reddens is not a control.
- Behavioral equivalence with pre-diff code is the FLOOR of a refactor review, not the verdict — also ask whether the preserved behavior was itself correct ("faithful to the old call-site literals" once approved a live merge-write data-loss bug). If a guard blocks a mutation, hand-trace and report as static-only — never claim a live result you didn't get, and **never carry a hand-traced EXACT COUNT forward as fact once the emulator is reachable** — BIN-941's archived count was contradicted by the live re-run while the qualitative conclusion survived; re-run it the moment the blocker clears and correct the archive. [arkiv 45]

## Mutation-testing protocol (the house method)
- Per criterion: edit the REAL prod file → run → confirm the expected AND ONLY the expected test fails → restore from a scratchpad backup (`diff -q` it byte-identical) → `git diff` shows only the real work → suite green → next. Never `git stash` mid-review (unstages staged files); never `git checkout --` a file that may hold other uncommitted work.
- **A mutation that cannot COMPILE under the file's own `strict: true` is not a real gap** — deleting a `=== null`/`!== null` guard feeding arithmetic or a comparison on a `T | null` parameter is a type error, not a silent behaviour change, so it never ships; check the nearest `tsconfig.json`'s `strict` flag (a read-only `node -e` arithmetic probe is enough to see the boundary hold, no need to demand a fixture for it) before filing a null-guard-removal as untested (BIN-1129 `friendRequestPush/logic.ts`, both `mayPushFriendRequest` and `isStaleFriendRequestPushMarker`).
- **PROVE the mutation landed before believing a green run.** `src/**` is MIXED — `page.tsx` CRLF, `nextPath.ts` LF — so a multi-line `perl -0pi -e` silently matches nothing and exits 0, and the green suite reads as "no test catches this", manufacturing false gaps. Splice by LINE INDEX preserving each line's own terminator (`text.split(/(?<=\n)/)`); after ANY mutation `grep -n` / echo OLD+NEW. A scripted loop with an unexpanded `$VAR` makes `cp` fail and the next mutation stacks on the previous. `cp`-restore can normalize EOLs — re-check with `git hash-object` vs `git rev-parse :<f>`, not `file`. **`core.autocrlf=true` here**, so blobs are LF while worktrees are CRLF and `git hash-object` applies the clean filter — a worktree/index sha MATCH proves nothing about EOLs. An "EOL-only normalization, content unchanged" claim must be PROVEN, not assumed: strip `\r\n`→`\n` from BOTH blobs in python and diff those (`grep -c $'\r'` on a piped blob is unreliable in Git Bash). [arkiv 46]
- Mutate the CALLER performing the side effect, not only the extracted helper — a helper can be immaculate while the Firestore write is unpinned.
- **Count CALL SITES, never files** for a freshly-introduced shared helper (`grep -rn '<newHelperName>' src/**`), requiring a fixture per site where it DISAGREES with the old field plus a null-fallback case.
- **Testing the HUB and the SUPPLIER does not test the MIDDLE LINK**: a component receiving a prop and handing it to a mocked bare-`vi.fn()` hook without asserting the call's ARGUMENTS is the gap — and the same topology recurs at a whole SHARED MODULE every consumer `vi.mock`s wholesale.
- Dual-guard fail-safes (`condA==null || condB==null`): mutate EACH independently — co-occurrence can make one provably dead (BIN-433); a COMPOSITE guard needs one fixture per term, including char-class terms (`code < 0x20 || code === 0x7f` needs a DEL fixture beside the `\n` one, BIN-645) [arkiv 88].
- For ≥2 sequential exclusion guards the fixture must pass every guard EXCEPT the one under test — and when the SAME condition is copied into two sibling effects, the fixture reaching it in one can be stopped by an EARLIER return in the other, so mutate per effect (BIN-816).
- **A "two shapes, one per AND-term" test needs each fixture to isolate its OWN term by satisfying every OTHER term** (BIN-808)

## Boundary & threshold completeness
- **A test that DERIVES its fixture size from the constant under test pins the loop and nothing about the constant's own ceiling** — `refs(DELETION_CHUNK + 1)` is right for the chunking but leaves `DELETION_CHUNK = 450` free to become 600 at full green; one line closes it: `expect(DELETION_CHUNK).toBeLessThan(500)`.
- Count how many surviving fixtures name a LITERAL on both sides — one is enough, none is a gap — and ask for a semantic literal case rather than an exact `toBe(5)`, which punishes legitimate tuning.
- `>=` vs `>` is the most-repeated regression here — pin the EXACT boundary from both sides: strict `<` → boundary−1/boundary/+1; `>= N` → >N,==N,<N; `used >= cap` → at-cap carries the load; four-sided window → below/at-lower/at-upper/above; `length >= 4` pinned from BELOW with a −1 twin. Staleness predicates: exactly-at-threshold AND one-unit-past, via epoch-ms arithmetic not `setDate` (BIN-183/184).
- **A SIBLING threshold added alongside an already-tested one inherits none of its coverage** — ask for the exact-N fixture whenever a new `MIN_*`/`*_CAP`/`*_THRESHOLD` const appears.

## Vacuous / non-discriminating oracles
- A strict SUBSET of a sibling proves nothing new: the real test is **can it fail ALONE?**, and **deleting a subset restatement is a legitimate cleanup, not a weakening** (BIN-646) provided the deleted case NEVER fails alone against a restored copy.
- **A test whose NAME lies is rename-and-annotate, not delete.**
- Keep IF a plausible mutation of the NAMED function flips it; rename to what it proves; delete only if NOTHING flips it (BIN-593).
- Empty-collection vacuity: `.every(e => e.kind === 'cancel')` as sole oracle is true on `[]` — assert length or a full `.toEqual([...])` first; every `offenders…toEqual([])` scan-guard needs a sibling non-vacuity test RUN against the real tree (BIN-356/370); set-equality needs `expect(setA.size).toBeGreaterThan(0)`.
- **When the EXPECTED side is ALSO derived by calling the same (possibly mutated) function under test, total destruction can collapse both sides to the same nonsense value and the comparison passes anyway; the baseline needs its own independent sanity assertion before it's trusted** (BIN-1069/1060's `expectSeenAt`, `firstAwaitIndex(body)` vs `firstAwaitIndex(mutated)`).
- Assert values, not shapes: `arrayContaining` is too weak for exact sets (compare as `Set`s); N-flag returns get a full-object `toEqual` per path (BIN-346); `toMatchObject` on a `merge:true` payload is blind to omitted-vs-null — use `toEqual`, or `not.toHaveProperty` per omitted field when a blanket `toEqual` would freeze a field under an open ticket.
- Coverage does NOT transfer between sibling output shapes, COMPONENTS, or consumers of the same fix — mutate each (BIN-169/349/596); indirect coverage via an old consumer's test is presumed non-discriminating until proven.- A cache-invalidation test must PRIME the cache first (BIN-510). An "unsorted input" test needs a fixture whose output CHANGES when the sort is dropped (BIN-185); `.sort()`-before-compare is blind to any order contract claimed (BIN-407). **A React-Query `queryKey` term IS a guard needing its own fixture** — BIN-564: dropping `mediaType` from `queryKey: ['x', mediaType, id]` shares one cache entry across movie N and TV N; every doc-id test still passes. [arkiv 59]

## Fixture-ordering discipline & filter→sort→slice pipelines
- Build fixtures so the WRONG implementation would win: first-wins candidate FIRST, true winner second for argmax; later/heavier value first for earliest-of-N; ascending input for a descending sort; NaN entry AFTER the valid max. Assert the winner's id AND the surviving subset, not just count. `.sort(localeCompare(...,'sv'))`: Set-insertion order must DIFFER from alphabetical (BIN-44). A trim-then-clamp write has THREE candidate strings (raw, trimmed, clamped) and a guard may compare against either raw or trimmed — the fixture needs padding AND over-cap length, or `prev === next` for `prev === sent` survives (BIN-1154/1275). Ordering doesn't reach a lookup that PARTITIONS by key — prove inert with a reorder probe, don't file it (BIN-608). **A "report the N OLDEST + a count" reporter needs THREE probes** (comparator reversed, sort deleted, sorted by the WRONG KEY) and fixture entries whose alphabetical order CONTRADICTS age order: [arkiv 29, 69].
- Pipeline must-have set: all-exclusion path; one mixed batch with a pass+fail item per condition, sort varied by a distinguishing field; cap at default AND custom limit (BIN-88). Assert derived flags directly — sort order can coincidentally survive a branch typo. Filter+attribution: one full positive `.toEqual`, one `.toHaveLength(0)` per skip condition. A rating/weight scale bug travels with an ORDERING bug — test scale and branch precedence separately (BIN-511).

## Extract-then-test & layering
- "Pure helper extracted, wiring untested" is accepted ONLY when production consumes the tested fn's OUTPUT verbatim — no re-derivation, no BRANCH of its own; a caller switching on the verdict owes a call-site test (BIN-611).
- Mock only the documented choke point: `vi.mock(path, async (importOriginal) => ({ ...(await importOriginal()), oneFn: spy }))` — full-replacement mocks make assertions tautological (BIN-164).
- **Mock/fixture arity must track the real API**: `onSnapshot(ref, successCb)` omitting `errorCb` misrepresents the SDK (BIN-596/601); diff the mock's FIELD list against the real one, not just params (BIN-645).
- **Full-module `vi.mock('@/lib/x')` is fine for testing the CALLER's orchestration, but grep for a sibling `x.test.ts`** — if none exists and it fully replaces the module, the real file's contract has zero direct coverage anywhere (BIN-657/669).

## Legitimate update vs cover-up
- Legit: the diff visibly implements the new contract, assertions stay strict, no unrelated assertion touched (BIN-16/17). **A strict→REGEX relaxation is an honest environment accommodation, not a weakening, only when THREE things hold and you PROVED the first**: the framework really does normalize the value (probe it — swap the exact form back in and READ the `Received:` line), the exact string is still pinned in the producing helper's own test (`src/lib/calendar/entry.test.ts`), and the component consumes that helper VERBATIM. Strict→different is legit only when production changed FIRST for a real reason (BIN-360/601). **A test rewritten to assert the OPPOSITE needs four things, all checkable in one mutation pass**: the reversal is equally strict, not looser; a NEW case accompanies it so the file GROWS; it is red against the OLD behaviour re-applied; and the ban's stated REASON is genuinely dead, verified in code and not from the diff's own comment — grep for OTHER live paths to the banned state before crediting an "unreachable dead code" claim (BIN-679). Cascade row: every full-array `.toEqual` must GROW — shrinking is the cover-up signal (BIN-175). Retiring a fn: old export gone EVERYWHERE (BIN-178); dropping assertions for a schema-removed field is correct (BIN-292). A `deleteDoc` bump 1→2 is legit when BOTH exact paths are pinned; guard+migration ship atomically (BIN-356). [arkiv 41]
- **Reverts get their own protocol, not mutation-testing:** blob-hash the index against the revert target; diff exported-symbol lists; test-count delta must equal the removed prod tests. Zero-test code reverted removes zero coverage. **In-batch revert** (undone pre-commit) leaves no trace in `git diff --cached`; confirm via `git show HEAD:<path>` and mutate the REJECTED design back in (BIN-593).

## When NO new test is owed
- One-line non-branching discriminants in hooks (`!snap.exists()→'ghost'`, bare `catch→null`) over a tested pure helper (BIN-21); prop-threading, conditional JSX, ARIA spreads, Set toggles (BIN-42); `useMemo`-only optimizations, zero-logic components (BIN-336); a JSDoc MOVED to the fn it describes or CORRECTED to drop a symmetry the code lost (BIN-616/618) — verify by running both copies. Byte-identical delegation to a tested helper (incl. a filter clause inert because a downstream `continue` already dropped it — READ that fn); a signature change threading its new param; pure I/O consolidation over a tested decision fn (BIN-541). Forward-prep with no reachable path; a defense-in-depth guard on a provably unreachable condition — don't demand a first RTL harness over one boolean loading-gate (BIN-596/595/601). **A "belt-and-braces, the real gate is elsewhere" defence must be checked PER SITE by NAMING the module that re-reads the underlying source, because two guards of the same shape in the same file can have opposite verdicts** — BIN-816: true for one early-out (re-reads the marker and refuses), FALSE for a sibling whose write path has no chokepoint. **A HARNESS hardening is the same class — hygiene, unpinnable, file nothing either way**: the honest report is "correct, strictly more robust, not mutation-detectable today", with the mutation you ran to say so. [arkiv 42]
- **Two exceptions override the exemption above:** (1) the ticket lists a test as an acceptance criterion — an unmet self-imposed bar is a gap even in an exempt shape; extracting the buried decision (BIN-599 → BIN-611's `planQuickRateWrite`) is only HALF the remedy, since the helper's verdict is inert until the CALLER is pinned obeying it. (2) the gate protects a counter/date the code calls permanent-and-uneditable (`rewatchCount`, `watchedAt`) — earns a test at one-boolean size; reserve the exemption for gates whose failure is a redundant render, not silent corruption.
