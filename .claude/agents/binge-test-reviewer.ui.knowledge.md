# binge-test-reviewer — ui chapter

Read only when the staged diff touches this chapter's paths (see .claude/shared-plugin.json → knowledge.tiers).

## Review protocol & scope discipline
- **Never weaken to go green** — strict→loose, deleted assertion, `.skip`/`.only`, an expectation rewritten to match buggy output: prod code is the suspect. **Pin derived state** (`watchStatus`, `libraryView`, `calendar/summary`, `airingState`, `migrateStatus`). A rules change with no `vitest.rules.config.ts` update (emulator, Java/JBR on PATH) is a gap; `src/lib/design/consistency.test.ts` is never disabled for a lazy change. **A handler→orchestrator split earns a pass only when four things are separately mutation-checked, not read off the file list**: delete a whole sweep/branch and require the failure to NAME the field it broke; flip any `-1`-died-vs-`0`-clean sentinel, and refuse a lone `null` standing for two outcomes with OPPOSITE consequences (delete vs. do nothing) — untestable by construction; break EACH of two sites sharing one ceiling predicate ALONE, other stays green; failed batch-commit still increments the "deleted" counter (BIN-727 `runCleanup.ts`). **Asserting a raw CSS/Tailwind class string is the RIGHT call when the class IS the fix and jsdom cannot compute the effect** (BIN-660) — then **one probe PER TERM, since a term is not covered by a probe on a NEIGHBOURING term**, and **a MODIFIER class does not pin the BASE class it modifies** (use `classList.contains('flex')`). Inline `style` numbers need `toHaveStyle` on the applying case AND `not.toHaveStyle` on the non-applying one. [arkiv 01]
- "An added test can only turn things RED" holds ONLY while the harness is untouched: a MOCK edit rewrites the contract every sibling runs under and can turn a prior RED green. **A new test can rewrite that contract from INSIDE its own body, which no harness diff shows** — `vi.mocked(fn).mockResolvedValue(x)` permanently replaces a `beforeAll` value for every later test (grep `vitest.config.ts` for `mockReset`/`restoreMocks`/`clearMocks` first); ask for `mockResolvedValueOnce`. **A PRODUCTION edit inside the mutated function does the same and is easier to miss, because the test file's blob never moved** — grade the survivor by REACHABILITY and report unreachable-by-construction as "the test's name now claims a property it cannot fail on", not "coverage lost". **For a self-graded "equivalent mutant" on a DUPLICATE side-effecting call the default verdict is the opposite — usually NOT equivalent** (BIN-727's redundant early `await writeMarker()`): build the cheapest assertion the claimed-equivalent difference COULD produce (a call count, an order, a written-twice check) and run it. When they yank the TOOLCHAIN mid-review, don't `npm install` on their behalf — substitute proxy greps and never inherit "typecheck clean, eslint 0 errors". [arkiv 05]
- **An uncleared mock forces the NEXT test into `.at(-1)`/delta workarounds — judge those as a symptom, not a defect, and check whether `mockClear()` was simply left off.** BIN-844: `signOutMock` was the only mock never cleared in `AuthContext.tsx`'s `beforeEach`, so its call log accumulated file-wide; the workaround was sound but papered over a one-line harness gap. Ask this whenever a test reaches for `.at(-1)`/`mock.calls.length` deltas instead of `toHaveBeenCalledTimes(N)`. Applying the fix can strand its justifying comment in the SAME diff — grep it against the `beforeEach` diff. **Inverse case, same test: a bare inline `mockClear()` before the measured call still needs deleting-and-rerunning to trust.** No `clearMocks` in `vitest.config.ts` → a `vi.hoisted` mock's calls survive across sibling `describe`s, so an exact-`toEqual` on `mock.calls` needs that clear; removing it must reden with CONTAMINATED extra entries, never pass silently (BIN-1172). [arkiv 07]

## Vacuous / non-discriminating oracles
- **A TRANSIENT render state is invisible to any oracle read at the end, and a single `await act()` collapses it** — the mutant that matters is a flag flipped ON at the start of an async run and OFF again at the end (BIN-816's `setDeletionInProgress(true)` beside `markDeletionStarted`). A per-render recorder (`const flagRenders: boolean[] = []` pushed from the harness component's body, cleared in `beforeEach` AND after any sign-in helper) is necessary but not sufficient, since inside ONE `act()` React batches the run into a single commit. Drive it as **hold → observe → release**: mock the first awaited collaborator to return a promise you control, `await act(async () => { pending = fn(); })`, assert, then `await act(async () => { release(); await pending; })` and assert again — pinning BOTH directions (happy path and the failure `catch`). Non-vacuity of the hold half needs a SECOND assertion proving execution reached the suspension point; without it, "no render carried true" is equally true of a run that never started. [arkiv 17]
- Ask "what plausible alternate implementation flips this?" — none means vacuous, however specific it looks. **For a MARKUP-VALIDITY / a11y fix the structural oracle is the strong one and the behavioural oracle the weak one**: only `expect(link.contains(button)).toBe(false)` catches a re-nested `<button>` inside `<Link>`; the role-based and tag-based containment checks are COMPLEMENTARY, not subsets. **A containment contract has THREE ends, each needing its own line: outside X, inside Y, and IN ORDER** — both containment assertions are order-blind, so ask for `compareDocumentPosition`/`lastElementChild` whenever the acceptance says "no visual change". **A PERIODIC emitter's "keeps reporting" claim is unpinnable by a single-tick oracle**: advance a SECOND interval and COUNT, then mutate the INTERVAL itself. **Each FIELD of a diagnostic log line is its own term.** **A test titled "never writes to X" that declares its own local `X` and never passes it into the function under test is vacuous by construction** — no mutation inside the function can fail that assertion for the right reason; verify by mutating the CALL SITE instead, swapping in the real forbidden argument (BIN-852's `checkBaselineStaleness` "never writes to problems" test reddened only via an unrelated `ReferenceError`, never via its own `deepEqual`). [arkiv 18]
- **Defense-in-depth double validation hides the first guard, once PER VALIDATOR**: when a value is validated on WRITE and re-validated on READ (`rememberNextPath`/`takeNextPath`, BIN-645), any test asserting through the reader passes with the write-side guard deleted. Assert the INTERMEDIATE directly, never the re-cleaned output — same shape for any strip/normalize-then-reparse pair. **Fixing it for validator #1 does not fix #2**: on any diff ADDING a read-side copy of an existing write-side cleaner, re-mutate the write side, and read a name of the form "is applied by X, not just available to it" as a promise to assert X's OUTPUT. [arkiv 47]
- **A `document` keydown listener in a CHILD dialog shadows the parent modal's own listener, so a nested-dialog gate test named for the parent's path cannot fail on it.** Listener ORDER is not stable: the child's effect flushes first at MOUNT, but a child listener carrying state in its dep array re-registers on every flip and then lands AFTER the host's (measured 2026-09-22 on `HandOverGroupDialog`'s `working`), so only the host's OWN guard is load-bearing — measured on BIN-1118: deleting `&& !handingOver` from `GroupSettingsModal`'s document handler alone left 10/10 green, deleting `HandOverGroupDialog`'s `stopImmediatePropagation` alone left 34/34 green, and only BOTH together reddened. Mutate each guard alone whenever a nested dialog and its host both listen on `document`; the honest closure is to stub the child dialog so the host's own gate is the only thing standing. The SYNTHETIC-path twin still bites separately: a key fired on an inner element of the child never reaches the host's backdrop `onKeyDown`, so drive the host's backdrop path from the trigger BUTTON (that is where focus actually is) — that half IS pinned alone here.
- The converse acquits most mocked-hook component tests: `not.toHaveBeenCalled()` beside a positive `toHaveBeenCalledWith` in the SAME `it`, and a CALL-COUNT beside an ambiguous-text selector (BIN-641). PROVE by deleting the component's whole write path (`void addItem; void updateStatus;`, keep the state call): green = hollow, red = real (BIN-611). Purely-negative tests still need a positive. **A hook-side guard keyed on an ARGUMENT the component supplies is only as good as the caller's literal, and a "the affordance now exists" test (`queryAllByRole('checkbox').length).toBeGreaterThan(0)`) pins none of it** (BIN-679). [arkiv 96]. **A forwarded BOOLEAN pinned at ONE value is a HALF pin — the SAME-value hardcode is always the survivor.** **A boolean claimed to matter for only ONE branch needs the OTHER branches asserted IDENTICAL across both its values, not merely truthy at each** — a per-branch×per-value truthy loop is blind to a branch that starts reading the flag too (BIN-1166's `joinLinkMessage`/`attemptsExhausted`, live-verified: 16/16 green). **One probe per RENDERING of a number, not per number.** [arkiv 19]
- **A React IDENTITY contract is pinnable and worth pinning** when a callback's dep list carries a value the body never reads (BIN-598: `setRuntime`/`refreshTmdbFields` list `items` so title-page effects re-run after the first snapshot). Shape: capture the ref, drive the state change, `expect(ref).not.toBe(before)` for EVERY callback named; mutate each dep-array term separately. Check the paired `// eslint-disable-next-line react-hooks/exhaustive-deps` sits on the line ABOVE the dep array — two lines up it suppresses nothing; with no disable, `exhaustive-deps` still only WARNS (CI blocks on errors), so a dropped dep is a silent ship. Same shape for a RE-READ effect's non-primary-key dep term (BIN-844) [arkiv 101]. **Pin BOTH directions of a NARROWED dep**: dropping it may be red-alone while WIDENING it back stays green unless a test clicks a NON-affected toggle and asserts the read mock's call count is unchanged. **A per-outcome fixture set misses a dropped RESET of a retry flag** — deleting `send()`'s `setSendFailed(false)` stays green sans a fail-then-succeed fixture (BIN-1129). [arkiv 23]
- **No dep-array term is pinnable while a mocked hook returns a FRESH object per call** — `useRouter: () => ({ push })` re-runs the effect on every render, so the whole array is inert and any test that seems to pin it is vacuous (BIN-645). Order of work: hoist the mock to ONE stable object (`() => { const r = { push }; return { useRouter: () => r }; }`), re-check the latch case still reddens under it, THEN add the transition fixture. **A comment claiming "ONE router object, hoisted" over `useRouter: () => ({ push })` is wrong and worth catching**: the `push` spy is stable but the wrapping object literal is fresh every call, so `useCallback(…, [router])` still recomputes — demand the FULL idiom the moment a dep-array or re-render-count assertion is added. **Two-phase async state needs the TRANSITION, not the settled end state**: render `profileLoading: true`, `expect(push).not.toHaveBeenCalled()`, flip to false, `rerender`, assert the push — red ALONE under the dropped dep AND under the twin latch-on-the-way-in mutant; one fixture, two named mutants, re-derive BOTH. [arkiv 24]
- **Hoisting a mocked hook to a stable object CHANGES THE IDENTITY CONTRACT EVERY OTHER CASE IN THE FILE RUNS UNDER** — it removes effect re-runs, so it can turn a previously-RED mutation GREEN. Treat it like an added `disabled` attribute: re-run every latch/dep/gate mutation in that file against the new bytes rather than carrying the prior verdict. Expect the count to GROW, never shrink; a shrink is the hollowing signal. Afterwards some terms are **provably inert by construction** — with a latch present only the first qualifying run matters, so terms the latch subsumes are inert; say that, do NOT file it. **A React Query `data` object is another provably-inert source**: a local `const derived = data?.field || fallback` computed fresh every render is subsumed by `[data]` alone, since structural sharing only preserves the `data` REFERENCE when a refetch is deep-equal — confirm the derived var reads ONLY fields of the already-listed query-data object before crediting the collapse. [arkiv 25]
- **A "runs once per mount" latch (`redirectedRef`) IS drivable under vitest — never accept "I couldn't force a second effect run".** Two triggers (BIN-645): a mock hook returning a FRESH object per call, or a fresh state object assigned before the second `rerender` — require the second, since with a stable mock the first goes vacuous. The trigger can also fire from the component's OWN bootstrap effect with no `rerender()` at all: instrument a render counter before crediting a "proves the re-run" test. [arkiv 26, 67-latch]
- **An async cancellation guard (`let cancelled=false; … return () => { cancelled = true }`) inside a re-running effect is provably dead unless a test drives TWO OVERLAPPING runs with the stale one resolving last** — a single held-then-released promise never triggers a second effect run (BIN-849: deleting `if (!cancelled)` left the file green). Fix: two distinct held promises, re-trigger via the real dep, resolve the OLDER one LAST with the opposite answer, assert the NEWER answer is on screen. [arkiv 28, 67-cancel]

## Extract-then-test & layering
- Flag "should have been extracted" when ALL hold: a sibling `.helpers.ts` exists; the block is Firebase/React-Query-free; tests only construct the block's OUTPUT instead of driving its inputs (BIN-410/411). Three inverses: stale-canonical-home (BIN-618), unreferenced-but-tested (BIN-580), untested-new-sibling (BIN-656/686) [arkiv 100]. A helper extracted in the SAME diff is born with the hole when every case holds one operand at the interesting value (BIN-641's `rewatchFields`) — mutate a two-operand predicate to its EQUALITY form and demand the equal-but-uninteresting pair. **A DELIBERATE divergence between the `src/` and `functions/src/shared/` copies of a mirrored helper is a comment-only invariant until the copy that did NOT change pins the behavior it keeps** — closed via a same-directory `*.parity.test.ts` importing BOTH real copies and mutating BOTH drift directions independently (BIN-636 `mediaTypeDocId`, rules-vs-client BIN-1002). [arkiv 31, 56, 69, 77]
- **A UI CONFIRMATION that restates a write decision is a SECOND consumer of the same helper and owes the same divergent-state fixture**. "It asks the same helper the write asks" is not enough: the caller also HARDCODES arguments the write computes, so **mutate every LITERAL passed into a shared helper, not just the gate**, and watch for a fixture detail that silences the assertion entirely. A term the helper already subsumes is equivalence-by-construction: mutate it, say it is inert, do NOT file it. Worked case (BIN-641 r4, `useMarkSeen`'s toast): [arkiv 51, 69]. **A new discriminated-outcome type can be fully mutation-tested at its SOURCE while every consumer branching on it has ZERO test coverage** — `grep -rn '<ResultTypeName>'` every importer before crediting the library-level suite as sufficient (BIN-1166's `AcceptInviteResult`/`JoinViaTokenResult`). [arkiv 97]

## When NO new test is owed
- When such a gate DOES get an RTL harness (BIN-596/645), mutate each layer separately — `current = notReady ? null : getItem(...)`, `disabled={notReady}`, each handler early-return, the refusal toast, the signed-out route (removed AND wrong path), BOTH terms of the auth gate. Mirror fixtures into BOTH siblings (QuickAddButton + StatusButton). The signed-out test must assert three things together — route taken, remembered return path (exact string, `.search` included), and the OLD consent-bypassing `signIn()` NOT called — and keying `signedOut` on the Firestore profile instead of `uid` must go red. Once `disabled={authLoading}` lands, BOTH in-handler auth guards are unreachable — don't call either load-bearing, and don't file the green mutation. The BIN-668 per-SIBLING `.search` case: [arkiv 52, 68].
- **Mocking the provider hooks pins the COMPONENT and leaves the PROVIDER's state machine unasserted** — `vi.mock('@/hooks/useWatchlist')` full-replacement is fine for exactly that scope, no more. Mutate the provider facts the component tests assume: `useState(true)` for `loading` → `false`, and any "deliberately stays true" branch (BIN-601's onSnapshot error handler) → `setLoading(false)`. Owed: `loading` assertions in the file rendering the REAL provider — true before the first snapshot, false after, false for a null uid, still true after an error callback. **A DERIVED boolean the provider exposes (`libraryKnown = snapshotSettled && !listenerFailed`) must be mocked as a GETTER computed from the same two primitives, never a settable literal** — a literal lets a test hand the component a combination production cannot produce, silently voiding every gate assertion in the file; grep-diff the mock's formula against `WatchlistContext.tsx`'s own derivation. Confirm reachability, not just the formula match: each of the 4 boolean combinations must be independently producible by the real onSnapshot callbacks — the easy-to-miss cell is "listener fails before ever settling". [arkiv 43]

## Parsers, regex, dispatch, lookup tables & SEO
- `\d+` parsers: test the syntactically-valid-but-semantically-invalid boundary (`/movie/0` → null); strict-digit hardening needs empty-string and phantom-id-0 cases (BIN-560). Regex tightening: a NEGATIVE + POSITIVE pair per pattern — negative-only passes even if the regex reverts (BIN-176); anti-over-rejection tests are as load-bearing as the reject side. `\b` after a hyphenated token false-matches `accent-soft` — use lookarounds. The `check-public-env.mjs` bare-key `S` case: [arkiv 54, 68].
- **A URL/route fixture is a factual claim: grep it back to the line that BUILDS it.** Plausible-looking invented routes recurred EIGHT times across BIN-640/645, once inside the fix for the previous one. Check three things per fixture — the route directory exists under `src/app/`, the query KEY is read by that page, and the query VALUE is one the app can actually produce. A fixture naming a surface the app never had keeps passing after that surface moves, so it pins nothing. Curated id lists, sitemap enumeration and a rejected-Error fixture feeding a message-sniffing branch take the same discipline — grep the string back to the line that THROWS it, not the constant's declaration: [arkiv 44, 69].
