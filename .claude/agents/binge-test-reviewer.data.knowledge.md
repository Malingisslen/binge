# binge-test-reviewer — data chapter

Read only when the staged diff touches this chapter's paths (see .claude/shared-plugin.json → knowledge.tiers).

## Mutation-testing protocol (the house method)
- **A stamp-DECISION composition at a call site is a separate mutation target from the shared derivation the same diff already swept**: BIN-814's `shouldStampProvidersAtAdd` had 8 dedicated tests and zero at its one call site in `WatchlistContext.tsx`'s `addItem`, because the harness's `newTitle()` type `Omit<…|'subscriptionProviders'>` means no fixture can even SUPPLY the field. Also mutate a `useRef` mirror to the closure state var (BIN-593), every shared-ref assignment, and duplicated constants. **Mechanical sweep across N sibling mutators** (BIN-598): diff the harness's ref list against the production export list — a function in NEITHER has ZERO coverage — and **a filed sweep-gap does NOT close itself**, so re-run the revert every round. **Same shape for a shared REFUSAL/guard helper**: call-tested in isolation plus an argument-text source-scan proves neither that the caller invokes it before proceeding (BIN-1107 r4). [arkiv 84] [arkiv 11]
- **A parameter-narrowing guard reachable only via a SINGLE current caller that hardcodes the safe literal mutates clean** — no fixture supplies the OTHER value the function's own type still permits (BIN-954: `updateProgress`'s `else if (opts?.addIfMissing && mediaType === 'tv')`, whose one caller `useEpisodeProgressWithSync.ts` only ever passes `'tv'`). Distinct from a provably-UNREACHABLE defense-in-depth guard (exempt): this one IS reachable through the public signature, just unexercised — report as a non-blocking gap (one fixture with the other value), especially when the mislabeled write would corrupt data. **A comment's ordering claim ("mark the ref AFTER not BEFORE the write, or a concurrent second call would…") is only proven by a test that drives the interleaving it describes** — report it as unverified, not confirmed. [arkiv 13]

## Boundary & threshold completeness
- Two-condition pure gate: both-true→true; cond1-false→false; cond2-false-at-boundary→false; cond2-false-above→false; null-sentinel→true (BIN-50). Range-gate+transform (`r>=1 && r<=10` then ÷2): below-min, above-max, non-finite, at-min — at-min pins guard AND transform (BIN-340). `Number('')`/`Number('   ')` coerce to `0`, not `NaN` — "present but blank" fallbacks need `Number.isInteger(x) && x>0`; test empty and whitespace-only. Value-set guards get a bad-TYPE case beside the bad-VALUE case. A TTL/cache/rate-limit claim needs an explicit expiry-crossing test (BIN-510). **A classifier mapping a whole RANGE to one outcome except named exceptions (`classifyStatus`: 4xx → 'rejected' except 404/429) needs the exclusion pinned as a SWEPT PROPERTY over the range** — known-code fixtures all survive a mutant reverting the range check to an enumerated list; only a `for (400..500)` property test catches the next unlisted code. **A minimum-length gate driven only by trivially-short fixtures never reaches the threshold's OWN boundary** — add one fixture AT the threshold. [arkiv 16]

## Vacuous / non-discriminating oracles
- Same blindness at a CALL SITE off a mocked write hook (BIN-611): the builder's own suite pins the BUILDER, not who calls it. **Strong call-site form for "flag X must never reach the store" (BIN-641): a KEY-SET DIFF of two writes** — `expect(keysWith.filter(k => !ALLOWED_DELTA.includes(k)).sort()).toEqual(keysWithout.sort())` — with three load-bearing conditions: the payload getter asserts `calls.length > 0`; the filter names EVERY key the feature legitimately changes AND the fixture SETS them; and the diff line is proved to fail ALONE by making an UNRELATED key diverge only on the flagged path. OR-filters need operand 1 explicitly false and 2 true; exclusion claims need a candidate excluded ALONGSIDE included ones. **A DETAIL→LIST shape-adapter's mapped field is proven only by piping it through the REAL downstream reader** — `toRowTitle`'s `origin_country` through the real `applyClientFilters` (BIN-583). [arkiv 22]

## Fixture-ordering discipline & filter→sort→slice pipelines
- Collision-prevention migration (`mediaTypeDocId`): distinct keys per type in every fixture = green while never exercising the collision — one fixture must seed BOTH types at the SAME raw key, asserting the untouched one survives (BIN-560).
- **A legacy→namespaced read-path fallback over a doc holding a MULTI-WRITER map merges per KEY, never per DOCUMENT** — fixtures need DIFFERENT participants per doc, and an attacker-writable doc id needs its canonical-form parser mutated both ways (over- and under-rejection): [arkiv 69].

## Sentinel / key-absence assertions & merge-write payloads
- **Firestore `merge: true`: explicit `null` DELETES stored data; an ABSENT key PRESERVES it.** "Fill every field with a default" in a payload builder is almost always wrong at a merge boundary. Every helper feeding a merge write needs an omission-vs-null test per field; ask not "does this match the old code" but "was the old null/omit choice ever correct" (buildAddPayload shipped live data loss under a "faithful refactor").
- **A new intent term OR-ed in FRONT of a data-loss guard silently disables ALL that guard's other protections while its comment keeps claiming them.** Shape `A && (newIntent || existingStrictGate)`: BIN-641's `opts?.countsAsViewing ||` before `canAutoStampWatchedAt(...)` let a COLD LOAD stomp user-authored `watchedAt`. Mutating the new term both ways proves nothing — **re-run the EXISTING guard's own fixtures with the new flag true.** Unreachable-today is no excuse on a PUBLIC context API. A count half and a value-overwriting half are TWO features — full-revert-probe each (drop / force TRUE / force FALSE / raw-flag form), each reddening a DIFFERENT named case. **Each successive NARROWING is a NEW untested branch the prior round's mutations do not reach**: mutate the NEW gate back to the PREVIOUS one, not just to `true`/`false`/deleted. If green it owes a fixture where the two DIVERGE (a TRACKED NON-'sedd' title) that also SEEDS the protected field (`watchedAt: 2019-04-02` on a `vill_se` doc), else both gates stamp and it is green for the wrong reason. A subset assertion is fine INSIDE an `it` whose other assertion discriminates; the subset rule bites only when the WHOLE test is the subset. [arkiv 50]
- **Sibling stamps with ASYMMETRIC guards** (`addedAt` on `current` alone; `tmdbFieldsRefreshedAt` on `settled && !current`) need a fixture where the guards DISAGREE (cold load, no `current`) — an all-settled fixture proves only the shared half. A predicate with TWO structurally-different TRUE branches needs a fixture per BRANCH (BIN-595). **A THIRD state added later** (BIN-601's `listenerFailedRef`) needs its own fixture diverging on the IDENTICAL empty-items state; its THIRD write site — the per-uid RESET in the subscribe effect — needs an account SWITCH fixture (`rerender` with `authState.uid` moved to `u2`). **A second clamp/guard call fed by a variable an EARLIER clamp already narrowed is shadowed by that earlier call in every fixture that takes the shared-variable branch** — `createSession`'s participant `displayName: clampToCodeUnits(params.hostDisplayName ?? hostName, MAX)` reuses the already-clamped local `hostName`, so the fixture with `hostDisplayName` UNDEFINED cannot kill a mutant that deletes this clamp's own wrapper (live-verified: only the sibling fixture supplying a RAW, unclamped `hostDisplayName` does). Net coverage can still be fine if that sibling exists — but grade the shadowed test as "proves the end-to-end value, not this call site" and demand the fixture that bypasses the earlier clamp (a distinct raw input on the SAME field) before crediting independence (BIN-1156).
- Conditionally-omitted fields: assert `'watchedAt' in result === false`, not a value check — catches wrong value AND spurious insertion (BIN-35/91); per conditional field, one written case + one `'key' in update === false` case (BIN-319). Recurring security/cost class: assert a payload does NOT contain `updatedAt` or a PII field. Two optional inputs → two DISTINCT sentinels. Allowlist/prune helpers: assert ABSENCE of a dropped field the fixture actually sets — value-checks on kept fields miss a spread-instead-of-allowlist regression (BIN-423); `toBe` for a pass-through.
- A per-group re-model pins BOTH this group's exact key set AND `not.toHaveProperty` on a sibling's (BIN-468). A field's null-on-other-status value can be an IMPLICIT status filter for readers — a merge write flipping it to omit-preserves needs those readers grepped for a now-needed `status===X` gate (BIN-593/598 `seenWatchedAt`); a consumer that stays green under that helper's mutation is equivalent-by-construction or untested — say which. [arkiv 60]

## Extract-then-test & layering
- Any `firebase-admin` **or** `firebase-functions/*` import makes a file's exports unrunnable under root vitest. Fix: split pure helpers into a `*.helpers.ts` / admin-free `config.ts` sidecar, re-exported from the old module so existing suites stay green UNEDITED (BIN-326/543); moving an export into an already-extracted admin-free file is a CI unbreak, not a weakening. **Verify the "unresolvable" claim, don't take the sidecar's comment on faith**: root `npm ci` never installs `functions/node_modules`, so a `vi.mock('firebase-functions/v2', …)` probe passing LOCALLY is no proof it passes in CI — check `.github/workflows/pr-checks.yml` for a `functions/`-scoped install. Require the wrong-root case to be LOUD: mutate the root and confirm `ENOENT` + `Failed Suites 1 / no tests`, never a green subset, then mutate one scanned production file and require exactly its own test to redden. **Never let a comment claim WHERE a compile error shows** — derive it; an "only the deploy shows it" clause is the false-`only` class and gets STRUCK. [arkiv 30, 73, 89]
- A `Promise.allSettled` fan-out is accepted untested pattern-copy ONLY while it merely degrades — an untested precedent doesn't grandfather NEW branching on top. PARTIAL vs TOTAL failure (rethrow, so RQ retry/Sentry fires instead of a false-success empty array) is real logic needing extraction+test (BIN-595/596).
- Don't accept "index.ts can't be unit-tested" wholesale: separate the stuck I/O from the extractable decision (BIN-463/464). Security guards in admin `.mjs` scripts have ZERO root-vitest coverage — say so. An invariant living ONLY in an un-extracted write-payload builder is not protected by the pure-half tests. **A single-AND-term data-hygiene guard bolted onto an existing tested predicate's call site is the cheapest instance**: BIN-856's `if (isIntentTitle(it) && Number.isFinite(it.tmdbId))` in `functions/src/streamingOffers/index.ts` — a non-numeric `tmdbId` can never be fetched AND never gains `checkedAt`, so it re-enters the quota-spending queue forever. `isIntentTitle` already lives in the admin-free, tested `logic.ts` with exactly one caller: fold the finite-check INTO it rather than leaving it stranded in the untestable loop. Recommend the move explicitly; don't just note the gap. [arkiv 34]
- Admin-SDK orchestrator otherwise stuck review-gated: factor its loop behind a narrow per-call port satisfiable by BOTH the Admin SDK and the client SDK against a real emulator (BIN-566). **N hand-built client-SDK copies of one port interface can all be REAL yet a new method CALLED by only one — typing forces every copy to implement it, proving nothing about whether its suite calls it.** Mutate each to throw, per harness (BIN-1147). **Two fields set to the IDENTICAL value make a field-selection mutant equivalent** — swap the field, confirm redness. [arkiv 97] **A "swap X, N tests redden" count for a predicate DUPLICATED across files is a SUM claim — attribute EACH copy separately** [arkiv 94]. **A file's own "NOT PROVEN HERE" disclosure list is a claim to audit for COMPLETENESS, not just accuracy** (BIN-727's `runAggregate.ts`). **A "neuter this guard" mutation must be checked against the fixture's ACTUAL values.** [arkiv 78] **A NEW sweep in a multi-sweep orchestrator inherits that file's ACCEPTED gap-class — but grade it by BLAST-RADIUS DIRECTION, not by consistency with siblings** (BIN-848); close it with a pure helper behind an injected port asserting surviving batches BY NAME, not by a counter. A test titled "writes X BEFORE deleting Y" via a fake ATOMIC port method, source-scan/template-literal blind spots, and a stubbed port-boundary return testing only the CALLER's crediting: [arkiv 35, 63, 64, 83, 102]. **When a ticket NAMES N guards, each needs its OWN failure-injection fixture — a green happy-path run (plus the OTHER guards' failure overrides) proves nothing about an untested Nth guard.**
- **A diff routing a previously-raw fetch through a DISK-CACHE helper (`fetchForBuild`) makes the suite read AND write the repo's real gitignored cache, so a verdict becomes machine-dependent — a passthrough spread-mock is the RIGHT fix and it is checkable**: remove the mock, point `TMDB_CACHE_DIR` at a dir holding the cached payload, and watch the all-fetches-reject case FAIL. **A `writeBatch().commit()` mock hardcoded to always resolve makes "mark the dedup ref before the write, not after a successful commit" structurally unverifiable** — give `writeBatch()` a `commit: vi.fn()` the test can REJECT (BIN-601/640). [arkiv 36]
- **Narrowing a shared write-guard from THROW-always to swallow-and-RESOLVE(outcome) changes the confirmation contract for every EXTERNAL caller that inferred success from "the await didn't throw", not just the guard's own tests** (BIN-942, `guardedItemWrite`). Grep every caller for a confirmation action (toast, `setState` retiring a UI row, analytics) running unconditionally after the `await` and require it to gate on the RESOLVED discriminant. Closing check: a matrix `it.each`, one row per guarded call site — refusal resolves `'refused'` AND is reported, any OTHER error still rejects, a landing write resolves `'written'` — plus each external caller's OWN before/after render assertion, since a mocked mutator proves the CALL happened but not that the caller read its return value. [arkiv 37]

## GDPR, PII, deletion & money guards
- Deletion-cascade correctness needs a running emulator rules suite, not traced refs. A compile-time field-coverage gate is classification-only; pair with skip-set pinning (BIN-328). Greps prove presence, never reachability. New user-owned subcollections flow through `KNOWN_USER_SUBCOLLECTIONS`. A destructure-before-write strip needs a key-absence check (BIN-505). Cross-check a shipped schema/listener against its review-panel plan doc — tests get "extended" to legitimize a vetoed design. **"Point of no return" ordering needs `invocationCallOrder` PER sibling call, not one for the pair** (BIN-844). **When an erasure and a STATE SWAP that also moves the FIND query touch the same document, the order is a mutation target, not a comment** (BIN-1063 steg 3's handover). [arkiv 97] **A write-list BUILDER assembled from several loops needs one fixture combining EVERY category with an ordered `toEqual`** — per-category or count-only fixtures miss a cross-category reorder (`memberTraceWrites`, BIN-1109: reordering left all 41 green). **A hand-enumerated uid-bearing FIELD set for an erasure owes a roster derived from the source, not a `grep` written in a comment** (BIN-1063's `TraceErasure`) [arkiv 76]. [arkiv 85] **A client-side "stop-the-cascade" guarantee pinned only by a MOCKED REJECTION needs the SERVER predicate proven** — extract an admin-bound `if (failed>0) throw` beside the decision; closed via `refusalForHandover` + an anchored, counted source scan. [arkiv 40, 66, 70]
- Money/catalog: never hardcode a live catalog-derived price — compute it from the lookup at assertion time (recurring BIN-403). Alias-map mirrors (functions vs src): derive expected from the single source of truth, mutation-test BOTH drift directions (BIN-420). Resilience claims get checked at CALL SITES (BIN-430/442). A test hardcoding an unexported const must NAME it in a comment. Hand-typed exported-constant literal vs DRY nit grading: [arkiv 58, 93].

## Rounding, jsdom, TZ/DST
- Rounding oracles need `.5`-exact fixtures (`79/2=39.5`: round=40 vs floor=39) (BIN-87); `Math.round(x*2)/2` with only an `x>0` guard snaps 0.25 to 0 — probe `0.1`. jsdom `getBoundingClientRect()` is always a zero DOMRect. **"Both directions plus the inclusive boundary" for a strict inequality (`a > b`) names TWO mutants, not one**: reversing the operator (`>`→`<`) tests DIRECTION and is silent AT equality, so only widening it (`>`→`>=`) pins "boundary is inclusive" (BIN-918's `commitDate > row.ts` gate). Both owed; try `>=`/`<=` before concluding a boundary claim is unpinned. [arkiv 53]
