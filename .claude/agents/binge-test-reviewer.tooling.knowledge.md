## Review protocol & scope discipline
- **A "comment says don't shrink this array" mitigation for a list-can-be-silently-shrunk finding is weaker than this repo's own established fix for the identical class, and a same-day precedent overrides a prior LOW-severity call to accept prose** (`docs/org/route.test.mjs`'s `GATE_SCRIPTS` against BIN-838's count floor). **Build it as a FLOOR, not an equality, and require the no-duplicate companion** `expect(new Set(GATE_SCRIPTS).size).toBe(GATE_SCRIPTS.length)`, proved by the decisive mutation: shrink by one real entry and pad back to N by DUPLICATING an existing one. **A floor DERIVED from the list's own length (`const MIN = REQUIRED.length`) is circular and can never fail alone** — hardcode it. **An EMPTIED array is silent — `it.each([])` registers ZERO tests with no error — so the floor is the ONLY thing between an emptied list and a green suite.** **A count floor over a UNION of sources is blind to one source vanishing when the survivors alone clear it**: demand one membership pin per source; likewise a test holding COPIES of a list in step (BIN-1426's four gates) is green when every copy retreats together — a widening owes a literal pin per added entry. Also owed: grep the whole file AND co-staged paths for other restatements of a corrected claim; RUN a regex a comment describes in nouns; a comment attributing a moved CI step to "workflow file X" needs both files diffed and ranked by `on:` triggers. [arkiv 06] **A ticket's own `events.jsonl` review rows are a checklist, not evidence a test exists** — grep the ticket's `must_haves` and confirm each BEHAVIORAL one (not "not leave an unhandled rejection", "must not lose every row when one item fails") names an actual test, since the panel that wrote it cannot see the code that ships later. BIN-1170 round 1: the co-staged `src/hooks/useNotifications.ts` rewrite (try/catch + `Promise.allSettled` replacing an atomic batch) had zero test anywhere. **A helper with TWO call sites needs a wiring test per call site** — a pure-helper test proves the per-item logic in isolation but never proves the hook calls it rather than the old mechanism. One call site tested is not both tested, even when they share one helper — nor when a second call consumes the same FILTERED input (BIN-1426: `gradeStagedRouting`'s feature fallback swapped `paths` for `stagedPaths` at full green). Drive each call site and live-verify it by reverting that call site alone. (BIN-1170 round 3; both call sites carry a mutation-verified test in the shipped commit.)

## Vacuous / non-discriminating oracles
- **When such a guard uses TWO regexes and `continue`s unless BOTH match, the non-vacuity test must pin the DISCRIMINATING one, not the cheap one** — BIN-816's chokepoint test exercised only one regex, so its partner matching nothing stayed green; assert each per LIST. **Write the probe for the idiom the diff does NOT use**, and when the fix WIDENS the pattern assert it against a LITERAL sample of each idiom it claims to cover. **An `…toEqual(Object.keys(OUT_OF_SCOPE))` exclusion-list guard is vacuous when production holds zero examples of the excluded shape** — BIN-1149's `single`-vs-`composite` collectionGroup classifier went `if (false)` with all 10 tests still green, since neither erasure directory has a real multi-`.where()`/`.orderBy()` query yet. Prove it with a literal synthetic source-string fixture per idiom, not by hand on the side. **A `toContain('gateFn(')` exemption assertion is satisfied by a DEAD call.** Values computed by the fn under test are tautological, as is a real browser API read straight back with no production code between — check the ORDER. **An `indexOf` boundary pair feeding `.slice` must assert both bounds were found first.** **A source-scan ratchet moved to a shared `beforeAll` cache reopens the same vacuity class one layer down**: interrogate the cache, throw on a miss (BIN-766/937). [arkiv 21]
- **A "check N is actually WIRED INTO main()" test built as a regex over the SOURCE TEXT of `main()`'s body cannot tell "called" from "the literal call-expression text is present but unreachable"** — `check-workflow-map.test.mjs`'s BIN-808 wiring test reddens on deletion or rewording of the call, but `if (false) checkBoundaryEnumeration(universe, problems);` stays green. Grade by realism: legitimate when nothing better exists, but its guarantee is "the call's TEXT wasn't deleted or reworded", not "the check runs" — note the gap, prefer an execution-based proof (a spy, injectable-I/O `main()`); accept as DOCUMENTED once the assertion states the blind spot. **A sibling check in the same file already paying for this wiring test makes a new check's total absence of one a gap, not a matching residual** — BIN-852's `checkBaselineStaleness` got none: deleting its call site left the whole suite green, silently disabling the feature forever. **Its regex must anchor EVERY positional argument, not just the first and last** — a `[^)]*` middle wildcard lets an arity-dropped call (missing `baseline`) still matches, green, while the function silently no-ops. Two anchor defects recur in the plain-`toContain` form [arkiv 71, 86]. **A bare `toContain(methodName)` scan is also satisfied by that method's own INTERFACE DECLARATION/JSDoc elsewhere in the file, regardless of whether the call site still invokes it** (BIN-1147) — check siblings first; an overclaiming NAME beats a fresh gap. **The same exact-text anchor is defeated by a defanged live branch plus an unreachable decoy holding an identical copy elsewhere in the file** (BIN-1107), and crosses syntax too (a `#`-commented lefthook.yml block, BIN-1110). Same accepted class: report as documented non-blocking, not a fresh gap. [arkiv 27, 67, 85, 86, 97] **A workflow text test that pins only a gate step's `continue-on-error` absence covers ONE of the routes by which the gate's refusal stops nothing** — `if:` on the gate step (and `/^\s*if:/m` misses the `- if:` first-key form), `|| true` in its `run:`, `if: always()` on the step it protects: pin the gate's `run:` by EQUALITY and `/^\s*(- )?if:/m` absence on BOTH steps. **The JOB-level twins are separate routes**: a job `if:` pinned per conjunct by `toContain` survives `&&`→`||` and an `always() ||` prefix (pin the whole line by equality), and once a later run reads this run's CONCLUSION (BIN-1426's last-successful-run base), job-level `continue-on-error` lets a failed job end in a successful run — the step-level form of that route being pinned does not cover it (BIN-1426, 2026-10-05 archive entries). **A `cmd | tee log` step's own success is a route too**: with no `shell:` the step runs `bash -e`, without pipefail, so its `set -o pipefail` line is all that fails it — and a pin on that line alone still lets `|| true` on the pipe, a later `set +e` or `set +o pipefail`, or a `tee`/`grep` log-path mismatch (grep's exit 2 reads as "not skipped") through: pin the WHOLE `run:` of a step whose success writes a record by EQUALITY, and pin `shell:`/`defaults:` ABSENT beside it: `shell: bash {0}` on the step, or as `defaults.run.shell` on its job or the workflow, drops the `-e` that equality-pinned script relies on, so a failed deploy ends green with the record written (BIN-1426 rounds 2–3, 2026-10-07); probe the absence pin with a QUOTED key too (`"shell": bash {0}`, `'defaults': {…}`), which `/^\s*(shell|defaults):/` lets through (round 4). **A branch slice anchored on a bare keyword (`indexOf('else', …)`) can land inside a prose word** (`händelsetyp`), leaving the "not in this branch" assertion vacuous: anchor on the whole indented line and assert it was found (BIN-1426, 2026-10-07).
- **A regression guard for a REKEYED rule is vacuous unless it calls the SAME exported function the rule runs, not a local reimplementation of the predicate.** `gate-symmetry.test.mjs`'s A1 rule (BIN-919) was rekeyed from `reasonCode === 'owned' || 'high-stakes'` to `tier !== 'skip'`, and the first draft of its own regression test declared a local copy of the OLD predicate inline, so reverting the real rule left the guard's own comment claiming it would go red while it stayed green. Fix: export the predicate (`a1Offenders`) and require the test to import and call it, never restate it — then reverting the rule fails exactly the dedicated regression case while the rest of the file stays green. Same family as the mocked-hook vacuity above: the test must exercise the article under review, not a hand-written stand-in for it, however faithfully the stand-in reads. [arkiv 48]
- **A live-tree text assertion anchored on `\n` (frontmatter `^---\n`) is red on the owner's CRLF checkout, and its `not.toMatch` twin is vacuous there** — require `\r?\n`; prove it by CRLF-converting the file and rerunning (BIN-1426 PR B). [arkiv 2026-10-06 PR B]

## Extract-then-test & layering
- **Run the FULL-REVERT probe on EACH side separately** (grep importers); the mirror side is often missed. 4 shapes archived [arkiv 32]. **A JSON accumulator file MERGED across REPEATED invocations is unpinned by a single-invocation fixture** — drive TWO invocations and mutate the merge step itself (BIN-1009): [arkiv 69]. **Any new THROW routed through a route's pre-existing `try/catch` owes a call-site `rejects.toThrow(<class>)` plus a positive twin proving the catch still absorbs a genuine failure** (BIN-823's `SelectionFloorError`), and **a belt-and-braces second guard is only a backstop if it can still SEE the failure**. **A CLI's own `main()` exit-code branch is the caller-switching class one level up** — ask for `expect(main(['--check'])).toBe(0)`, and a text pin on the dispatch line AND the inner call never reaches it: BIN-1426's two gate modes had both, yet `return 1`→`return 0` survived the whole file; a pin RED in the clean control kills nothing, so credit only control-green tests (BIN-1426: `main(['--check'])` was red on an unrelated gap and blind to `main()` handing `findGaps` other gates); **a `--check` "writes nothing" claim asserts `statSync().mtimeMs`, not content**; **a ratchet with an asymmetric policy is tested asymmetrically, never by equality against the baseline**; **two lists that must agree get ONE hoisted constant iterated on both sides** (BIN-830). **A missing-required-argument test needs the FALLBACK it silently takes to be resolvable in the fake, or the guard's deletion hides behind an unrelated ref failure** (BIN-1088's `main([])` vs the defaulted `'HEAD'`): [arkiv 69]. **Injected `git`/`gh` are blind to the REAL runner's options**: when a diff grows what the real command returns, measure the real answer and ask for one execution through the exported options with a bigger fixture, asserted as a STRING (`toHaveLength` also passes a Buffer, leaving `encoding` free) — BIN-1426 round 2 dropped a server-side filter, the run list grew past `execFileSync`'s 1 MiB default, and `--since-last-deploy` and `--site-gate` would have died ENOBUFS while every injected test, and my pass, stayed green. **The opposite shape, a throwaway repo driven by REAL `git`, inherits `process.env` and global config**: a leaked `GIT_INDEX_FILE`/`GIT_DIR` sends its `git add`/`commit` into the OUTER repo's index with the test still green, and a global `core.autocrlf=true` + `core.safecrlf=true` reddens its `git add` of LF fixtures. Ask for `GIT_*` stripped from the helper's env and `core.autocrlf false` in the fixture's local config. Probe that leak only from a scratch clone: run in the live checkout, my own probe emptied its index (BIN-1426 PR B round 2, restored with `git read-tree HEAD`).
- **A seam whose value is composed from constants and then read back through a git-dependent function keeps producing false absolutes** — export the composing constants and assert the join DIRECTLY [arkiv 33, 57].
