# Lessons Digest — testing

Lessons that only bind while writing or running tests. The lessons guard counts this file with the core
digest (`knowledge.digestFiles`); it loads when a test file is read.

- [Testing] Vitest's on-disk transform cache (`node_modules/.vite/vitest`) serves the PREVIOUS mutant after a source restore — 2026-08-01 (a "dead" guard at 7/7 green that was load-bearing). `rm -rf` it before EVERY mutation run AND the clean control. Same family: `git diff --ignore-cr-at-eol` ignores a trailing CR but not a lone one, and an LF-assuming patch tool in a `core.autocrlf=true` worktree exits 0 having changed nothing. Assert the patch landed.
- [Testing] A test that pins only that a wait STARTS is blind to the mutant that never ends it — BIN-645's login gate looked covered but a latch-on-the-way-in mutant passed it while stranding every returning visitor. Drive the whole transition: hold → flip → rerender → assert the action fires. And hoist the `useRouter` mock to ONE object — a per-call factory makes every dep-array assertion in the file vacuous. (2026-08-01)
- [Testing] A sprint worktree has NO local `node_modules`, so `rm -rf node_modules/.vite/vitest` is a silent no-op there — get the guarantee directly instead: `grep -n MUTANT <file> && npx vitest run <test>` as ONE command. Related: `vi.getTimerCount()` can't prove a hook cleared its own timeout when React/React Query keep unrelated timers alive — spy on the faked `setTimeout`/`clearTimeout`. (2026-08-03)
- [Testing] A script whose CLI runs at import cannot be tested — it eats the test runner's argv, and the symptom is vitest hanging with NO output, not an error (BIN-802). Guard the CLI behind an entry-point check and wrap it in `main(argv)` first. A test file outside the runner's `include` globs is silently never run — check the globs, add one additively. (2026-08-09)
- [Testing] Ett tillstånd som uppstår och försvinner syns inte i slutläget — driv hold → observera → släpp med en styrbar promise. Ett enda `act()` runt hela körningen batchar bort mellanläget. BIN-816:s "limbo-skärmen får inte visas under en normal radering" tog tre försök innan den bet. Ett test som sätter förutsättningen fel når aldrig grenen det testar och är grönt av fel skäl — en markör satt före inloggning gör profilen null, så effekten återvänder innan spärren. (2026-08-13)
- [Testing] Ett `.mjs`-skript med CRLF kan inte ens PARSAS av vitest på Windows — Vites shebang-strippare är LF-only, så ssr-preludiet hamnar framför shebangen och rolldown dör på `Invalid Character !`. `npm test` hoppar då TYST över sviten lokalt medan CI på Linux är grön. Pröva hypotesen med en ORÖRD granne innan du misstänker din egen ändring; kör mot LF-normaliserade kopior. (BIN-891, 2026-08-16)
- [Testing] En trasig JSON i en DATAFIL ser ut som hundratals orelaterade testfel — kör HELA sviten efter varje redigering av en fil andra test läser som data, och verifiera parsningen separat med `node -e "require('./<fil>')"`. Symptomet pekar åt fel håll. (2026-08-25)
- [Testing] En ny check som bara testas DIREKT kan raderas ur `main()` med hela sviten grön — "spärren finns" och "spärren körs" är olika påståenden (BIN-776:s form). Lägg en test som källkodsskannar `main()`s kropp och pinnar ARGUMENTEN. Tre mutationer ska fälla den. BIN-852 verifierade båda hålen på riktigt. (2026-08-29, BIN-852)
- [Testing] En assertion om att något INTE hittas uppfylls också av en förstörd mätning — pinna det positiva utfallet, inte frånvaron. Om den FÖRVÄNTADE sidan härleds genom att anropa samma funktion som prövas, kollapsar båda sidor till samma meningslöshet — baslinjen behöver en egen rimlighetskoll. (2026-09-02, BIN-1069)
- [Workflow] Fixen för en tyst spärr kan återinföra exakt den tystnad den stänger — räkna upp båda felriktningarna före bygget och pröva den TYSTA med en mutering. Trädet måste stå STILLA under push-granskningen. (2026-09-02, BIN-1069/1067/1074)
- [Testing] Ett test som pinnar en delad konstant på dess VÄRDE uppfylls av vilken KOMMENTAR som helst i filen som nämner värdet — ankra på deklarationen, aldrig på värdet ensamt, och pröva med en omdöpning på andra sidan. (2026-09-02, BIN-790)
- [Testing] En miljövariabel som läses i funktionens KROPP slår tyst ut en injicerad parameter, och när den utslagna vägen rör skarpt tillstånd raderar testet produktionsdata. Läs miljön i SIGNATUREN så ett test kan skicka `null` och verkligen få sin egen katalog. (2026-09-02, BIN-790)
- [Workflow] Ta ögonblicksbilden av ARBETSTRÄDETS bytes före en mutering, aldrig av indexet — `git show :<fil>` och `git stash` ger indexversionen. Verifiera med `git hash-object`, och `git diff` efter varje återställning mot det du TRODDE du hade. (2026-09-05, BIN-1088)
- [Testing] Ett mockat test bevisar anropets FORM och utvärderar inga regler. Ett påstående som korsar den gränsen behöver ett emulatortest; skriv i testets kommentar vilken av de två sakerna det bevisar, och lägg omfånget i testets NAMN. (2026-09-05, BIN-1063)
- [Testing] En matning byggd mot ett filnamn ramverket inte skriver ar en permanent TYST no-op — lasaren hittar inget, ser likadan ut som en frisk korning. BIN-613:s rapport hade tigit vid varje deploy for alltid. Kor mot repots RIKTIGA byggutfall en gang fore granskning, och lat "korde och hittade inget" skriva en synlig rad. (2026-09-06)
- [Testing] Ett nekande-test bevisar inget om VILKEN klausul som nekade - fixturen maste uppfylla varje klausul FORE den testet namnger. Ett `get()` pa ett dokument som inte finns KASTAR och nekar hela regeln, sa en oseedad anropare maskerar allt efter sig. (2026-09-09, BIN-1127)
- [Testing] En nekad `onSnapshot` är DÖD och startar inte om när reglerna senare släpper igenom samma läsare — varje skrivning som ÄNDRAR regelutfallet måste riva och återstarta prenumerationen. ett test som mockar `subscribe*` kan fyra success-callbacken för hand: det pinnar tillståndsmaskinen och är blint för buggen (BIN-1152). Pinna att en NY prenumeration öppnas, och att sidan anropar den. (2026-09-13)
- [Testing] En fixtur som seedar ett TOMT men rätt-typat fält gör den tysta muteringen högljudd — pröva uttryckligen `resource.data.X` i stället för `request.resource.data.X`. Saknas fältet i seeden är muteringen tyst. (2026-09-16, BIN-1195)
- [Testing] Ett muteringsharness vars RENA KONTROLL inte går att läsa gör "mutanten dödad" och "mätningen förstörd" till samma sträng — kör kontrollen först och gör den till ett ABORT-villkor. Läs exit-koden och antalet FÄLLDA test — en `passed`-siffra matchar gärna raden om testFILER i stället för testraden. (2026-09-17, BIN-1209)
- [Testing] Ett test som påstår att något är TILLÅTET måste prövas mot vad som gällde före ändringen — annars bokför det en oavsiktlig vidgning som om den vore ett krav. BIN-1207: mitt eget test sa att en samredigerare får skriva på ett dokument utan `items`; det nekades före bunten. (2026-09-17)
