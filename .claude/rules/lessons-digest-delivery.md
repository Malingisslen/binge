# Lessons Digest — delivery and review gates

Lessons that only bind while running a sprint, working with Linear, the review gates, the router or the
workflow map. The lessons guard counts this file with the core digest (`knowledge.digestFiles`), so these
are as in force as any other lesson; they load when a matching file is read.

- [Workflow] Never bundle `docs/workflow-map.html` edits with feature code — a feature-revert silently drops flow docs bundled in the same commit, and the coverage linter stays green. Bit us 2026-07-10 (BIN-422/423). Keep map edits in their own commit. BIN-459.
- [Workflow] A ticket body in the past tense ("now implemented") is NOT evidence the code shipped — grep the tree for the target symbols before classifying anything obsolete or skipping it. BIN-569's body described its own fix as built. The grep-of-main premise check cuts both ways. (2026-07-28)
- [Workflow] A batch you cannot reverse-apply holds the ENTIRE sprint hostage — withdrawability DECAYS, so `git apply -R --check` every batch patch right after apply and BEFORE any post-apply fix touches the tree. On failure, rebuild from clean HEAD with only the SURVIVING batches — never force it. Cost the 2026-08-01 sprint all six batches (BIN-683).
- [Workflow] A gitignored target is invisible to every diff-based gate, so the ticket EVAPORATES instead of failing — `.claude/**` work doesn't appear in any `git diff`, so "no diff" reads as "no work" to every gate. `git check-ignore -q <path>` at SELECTION time; a hit means Tier D + a comment, never a batch. BIN-585 was silently dropped by two consecutive sprints this way (BIN-684).
- [Workflow] A batch that produces NO artifact is indistinguishable from one never selected (2026-08-03: BIN-664/659/669 left no patch, no stash, no note, no comment). At close-out, assert one of {commit, patch, stash, written failure} PER selected batch. Date-namespace the patch files, and when work exists but didn't land, write "built, recoverable from stash@{N}" in the ticket. (BIN-707/708)
- [Workflow] A tool call the classifier BLOCKS still poisons every subagent you launch afterwards — a refused edit to shared automation stays in the transcript, and workflow subagents are sidechains of that session: on 2026-08-03 five of them re-attempted the same refused engine edit and were each blocked, including every APPLY and COMMIT agent. Never edit shared infra from a session about to launch subagents; if one is refused, treat the session as contaminated and route around the defect in DATA.
- [Workflow] A patch file whose hash matches another patch already in the directory is NOT an artifact — "nothing was built" and "the work is done" are identical to any existence check. The 2026-08-03 sprint selected BIN-704/707/708 and then lost the trace for half its OWN batches: BIN-638's real green work sat STAGED in the index in no bucket at all. Hash every batch patch against every other at close-out, disqualify duplicates from satisfying the per-batch assertion, and require `git status --porcelain` empty before writing a single Linear transition (BIN-713).
- [Workflow] A per-ticket outcome verifier handed the WHOLE batch's diff writes the batch's verdict under one ticket's name — BIN-701 came back `data-safety=fail` and withdrew all of BIN-596/598/617/701, while BIN-705's grading recorded the same ticket as PASS. Slice the diff to the ticket's own hunks before dispatch; a verdict whose severity is impossible for the diff's size is a mis-attribution signal, not a finding. And write a FAIL onto its ticket the moment it is issued (BIN-712).
- [Workflow] A `top`-tier ticket handed to a worker that CANNOT convene the stakeholder panel loses the panel silently — BIN-732 was dispatched to a batch agent with no subagent capability; it self-noted the roles' stakes and flagged the panel "still owed" at the commit gate, where the only remedy left is discarding finished code. Check the tier against the WORKER's capabilities at dispatch, not at commit; and read review evidence per-FILE. (2026-08-04)
- [Workflow] A sprint that commits per-batch must TRANSITION per-batch too — 2026-08-05 pushed four batches to main and wrote zero Linear transitions, leaving all six shipped tickets in `Todo` stamped with the SELECTION window. The BIN-707/708 evaporation class run backwards. Assert `{commit, transition}` as a PAIR per batch, written by the committer (BIN-754).
- [Workflow] "Not built this sprint — needs your decision" is a BINDING parking brake, and a note the sprint writes into a ticket's description is not the founder answering. BIN-700/643/729 were parked; the 2026-08-05 sprint built option (a) anyway. `list_comments` before implementing; a parked marker is an exclusion, never a downgrade.
- [Workflow] A capability check that lives INSIDE the worker fires too late to be a gate — 2026-08-05b routed four tickets (BIN-766/760/468/689) to `medium`/`single`, handed them to batch agents that structurally cannot convene a critique; all four were withdrawn at the commit gate. BIN-744 is recorded as shipped and installed exactly this check — in the worker. A precondition on whether work may START belongs to the party handing it out: run `docs/org/route.mjs` in SELECTION, match the tier against the planned worker, drop or re-route anything above `skip` before spawning. When auditing a shipped rule, check WHERE it runs. (BIN-776)
- [Workflow] Never write "acceptance criteria met" into a ticket from inside the build — BIN-766's batch agent `save_issue`d three filenames and "Acceptanskriterierna 1–3 är uppfyllda" into the description; the batch then failed verification and was stashed out, leaving a Todo ticket that described itself as finished. The BIN-569 lesson running FORWARD. Mid-build ticket writes may only say "designed/attempted/rescoped, NOT committed"; completion claims are written by whoever holds the commit sha. Withdrawing a batch includes correcting the text that batch already wrote. (2026-08-05)
- [Workflow] A hold reason inherited from a PRIOR run's plan text outranked the deterministic router — 2026-08-06 withdrew BIN-759 and BIN-468. Re-run the router on the batch's ACTUAL files at selection, every run; never inherit a tier from a plan, a ticket comment, or a previous withdrawal note. (BIN-787/788)
- [Workflow] Two lists decide who reviews a change and widening one never widens the other: the router ADVISES, `reviewGates` BLOCKS. BIN-805 shipped "route.mjs is code" into the router; the gate's patterns still match nothing under `docs/` or `scripts/`. Change both in one commit and prove the blocking one with a staged-diff probe. (BIN-830, 2026-08-09)
- [Workflow] Derive every per-ticket disposition at close-out from the TREE, never from the worker's self-report — 2026-08-12 reported "nothing was attempted" onto BIN-851 AND BIN-803 while files sat STAGED. A "never ran" claim against a non-empty `git status --porcelain` is a contradiction to fail on; the tree wins and the false comment gets corrected in the same pass. (BIN-707/708/713, BIN-866)
- [Workflow] En kapacitetskoll vid utdelning måste täcka VARJE tier över `skip` — BIN-744/776 skrev regeln bara för `full-panel`, så sprinten 2026-08-16 drog korrekt ut BIN-909 (`top`) och lät samtidigt BIN-908 och BIN-880/906 (`medium`) committas och pushas med den blinda rollkritiken oskuldad. "Bygg den, men parkera för påseende" är inget skydd: kritiken körs då aldrig av någon. Läs regeln där den UTLÖSER, inte bara där den skrevs. (BIN-917)
- [Workflow] Kanalen som följdbiljetter filas i kan vara FULL — `create_issue` svarade "You've exceeded the free issue limit" på sju följdbiljetter i post-sprinten 2026-08-16. Skriv varje fynd som en fullständig kommentar på närmaste befintliga öppna ärende, märk varför det inte blev en egen biljett, upprepa HELA listan på ett ställe, och rapportera taket som något Malin måste åtgärda. Annars blir "kunde inte filas" och "hittade inget" samma sträng — BIN-707/708:s evaporationsklass. (2026-08-16)
- [Workflow] Granskarens RAPPORT om vad den last ar inte bevis — granskningsloggen ar. Push-grinden kraver EN korning som tacker allt. Grep loggen sjalv pa `git rev-parse HEAD:<fil>`-shan innan du kor om, och begar ett kontrollerbart bevis i stallet for en sammanfattning. (BIN-766, 2026-08-19)
- [Workflow] Commit-grinden läser granskarens SISTA domrad, inte om fyndet är lagat — en `fail` blockerar tills SAMMA granskare kört om och slutat på pass. Kör om med `Read` på varje fil. `review-coverage` kräver en STAGEAD `review`-rad i `docs/org/metrics/events.jsonl`. (BIN-954, 2026-08-20)
- [Workflow] En hållen patch FÖRFALLER, och biljetten som beskriver den åldras tyst — kör `git apply --check` vid URVALET varje körning, ärv aldrig ett "går rent mot HEAD" ur biljettexten. BIN-972 redovisade sex filer och noll fel 2026-08-23; samma kommando gav sex fel 2026-08-25, den första för att BIN-989 döpte om `.claude/hooks/map-freshness.mjs`. Och när den inte längre går rent: läs patchen hunk för hunk mot trädet — bygg inte om den blint. (2026-08-25)
- [Workflow] En granskare kan läsa SIN EGEN definition i stället för filen den grindar och ändå avsluta på pass. Härled granskarens skyldiga fillista ur `reviewGates` själv före commit och jämför med rapporten; räkna med ett omkörningsvarv i budgeten. (2026-08-25)
- [Workflow] En muteringsprövande granskare kolliderar med en LÄSANDE, inte bara med en annan muterare. Kör muterande granskare en i taget, och integrationsgranskaren SIST mot ett städat träd — den är push-grinden och måste läsa exakt de bytes som går ut. (2026-08-26)
- [Testing] En grön bunt är inte en grön svit: en NY fil under en katalog ägarkartan listar fil för fil är en ägarkartshändelse. `src/lib/markedSeen.ts` var grön i varje per-bunt-körning och fällde två test i `docs/org/gen-ownership-map.test.mjs`. Ge filen en ÄGARE i `docs/role-responsibilities.md` och regenerera — aldrig `--update-gaps`, som gör hålet permanent (BIN-1013). Kör hela sviten före push. (2026-08-26)
- [Workflow] En ändring som gör en fil sannare kan göra en GRANNE falsk, och bara en helhetsläsning ser det. Kör helhetsgranskaren SIST och ensam, och kör om den efter varje rättelse — en rättelse är precis den sortens ändring som falsifierar en granne. (2026-08-27)
- [Workflow] En spärr inkopplad i en funktion ingenting anropar är overksam just där felet rapporterades — kontrollera vilken KODVÄG som fäller, inte vilken som ser ut att vara ingången. Bygg indata på EN plats båda anroparna använder, och härled anroparna med `git grep -n "findCoverageGaps(" -- docs`. (BIN-1040, 2026-08-29)
- [Workflow] En strykning i en commit lämnar kopian i nästa commit stående, och bara push-grindens helhetspass över HELA området ser det — varje per-bunt-granskning ser en bunt och passerar. Räkna inte kopiorna — stryk. (BIN-1040/1002/1038, 2026-08-29)
- [Workflow] En bunt kan göra en mening falsk i en fil den inte rör alls, och ingen per-fil-grind kan se det eftersom filen inte står i diffen. Fråga vid varje bunt vilken fil BESKRIVER det du ändrade beteendet på; att laga det beväpnar om den filens granskare. (BIN-1038, 2026-08-29)
- [Workflow] En KRYMPT filuppsättning ogiltigförklarar routningen precis som en vidgad — kör routern på buntens FAKTISKA union strax före kritiken konvenerar, inte på urvalets. BIN-766 skrev regeln bara för ett vidgat omfång; BIN-776 lade kollen i urvalet, där den körs EN gång och aldrig om när en biljett faller bort. BIN-790 drogs ur, den krympta unionen ger `[4]`, och den ägande rollen nåddes först av push-grinden. Skriv aldrig en mening om vilken FIL som flyttar panelen — svaret är ett kommando i planen. (2026-08-29, BIN-1050/1048)
- [Workflow] Ett bevis som mäts mot en datafil samma commit ÄNDRAR måste tas FÖRE ändringen, och sparas ordagrant — annars är enhetstestet mot din egen fixtur det enda beviset. Beskriv härledningen mot en TIDIGARE version av datafilen, och kör den innan du skriver meningen. (2026-08-29, BIN-852)
- [Workflow] Planens egen GRUPPERING kan vara det som felsätter panelen — routa på biljetternas union av filer, inte på meningen om dem, och routa om mot `git diff --cached --name-only` omedelbart före commit. Min plan skrev "de rör samma två filer" om tre biljetter; BIN-938:s hela leverans låg i en TREDJE fil, och just den vänder `reasonCode` från `unmapped-code` till `owned` och panelen från #14 till #25. BIN-1050/1048 i VIDGANDE riktning, en dag efter att den skrevs. Åtgärden är inte en omformulering utan att COMMITTA SPLITTAT så varje commits filuppsättning routar till den kritik som kördes. (2026-08-29, BIN-938/1052)
- [Workflow] Push-grinden är ett EGET granskningsvarv, inte ett `git push` — kräver EN körning som läst varje granskningsbar fil i hela `@{u}..HEAD`, och per-bunts-granskningar summerar inte till det. Budgetera det som ett varv med samma vikt som en bunt. (2026-09-01, BIN-1059)
- [Design] Nar bada de arliga svaren pa "ska den har filen granskas?" ar fel, granska en NYCKEL i stallet for sokvagen -- och bygg armen i VARJE grind som laser samma konfig. Bevisa genom att stanga av matcharen OCH tvinga den till sant. (2026-09-03, BIN-990)
- [Testing] `git stash show <ref>` listar bara SPÅRADE filer — en bunt stashad med `-u` bär sina nyskapade filer men rapporterar dem inte utan `--include-untracked`. Driv ett test med en NYSKAPAD fil, inte bara en ändrad. (2026-09-03, BIN-1082)
- [Workflow] Ett backtick-citerat KATALOGTOKEN i rolldokumentet ger rollen HELA katalogen, inte bara filen. Skriv sådana omnämnanden utan backticks, och läs rollens mönsterlista efter regenereringen — aldrig bullettexten. (2026-09-05, BIN-1080)
- [Workflow] Samma mening granskas av OLIKA grindar, och varje grind ser bara sina egna filer — ett underkänt påstående överlever därför i den fil grinden inte öppnade, så sök det i hela trädet innan du rättar. Undantaget för `*.knowledge.md` gäller: den ersätts på plats, den stryks inte. (2026-09-05, BIN-1063)
- [Workflow] Agarskap harlett ur en KATALOG ar inte agarskap — satet foljer vilken storhet filen handlar om, inte var dess data rakar ligga. kor routern igen efter en omflyttning, ett byte av sate ar en omfangsandring precis som ett tillagg. (2026-09-06, BIN-613)
- [Workflow] Push-grindens helhetslasning hittar defekter INGEN per-commit-grind kan se — budgetera den som flera egna varv. Fraga vid varje bunt vilken rad PRODUCERAR signalen du just borjade konsumera. Mutera producenten, inte bara konsumenten. (2026-09-07, BIN-1063)
- [Workflow] Routningen flyttar sig MEDAN bunten byggs, och varje flytt ar en egen kritik — kor routern pa den faktiska unionen fore varje kritik och fore varje commit, aldrig arvd ur urvalet. BIN-1122 routade tre ganger. Ett byte av SATE ar en omfangsandring precis som ett tillagg eller en krympning. (2026-09-09)
- [Workflow] Push-grindens dom ar ledgern, aven nar granskaren sager `pass` - rakna inte varvet klart forran `git push` slapper igenom. Begar ett kontrollerbart bevis (citera forsta raden i varje fil) och budgetera ett extra varv. Samma klass som 2026-08-19:s post. (2026-09-11, BIN-1134)
- [Workflow] Ett tal i en loggrad ar lika omatt som ett tal i en kommentar - `docs/org/metrics/events.jsonl` ar granskningsbevis och lases av grindarna, sa en oraknad siffra dar ar varre, inte battre. Filen ar append-only aven for en rad som aldrig pushats. (2026-09-11, BIN-1154)
- [Workflow] En panel kan vara akta OENIG, och da ar ordningen mellan biljetter svaret - inte en kompromiss och inte att valja sida. BIN-1155: sakerhets-, jurist- och dataskyddsrollen kravde en identitetsbindning och blockerade utan den. Bygg ingendera, skriv ut bada sidorna pa biljetten, lank den som blockerad av den biljett som loser laget, och lat Malin avgora. (2026-09-11)
- [Workflow] Routningen flyttar sig MEDAN bunten byggs — kör routern mot `git diff --cached --name-only` före commit och jämför med panelen som faktiskt kritiserade. 2026-09-12 växte unionen, panelen bytte #26 mot #18, som inte sett en rad kod. BIN-1050/1052 skrev regeln för en KRYMPANDE union; det här är samma sak åt andra hållet. (BIN-1155/1166)
- [Workflow] En KRYMPANDE stageuppsättning kan dra IN en roll som inte sett någonting — en commit-splittring krymper uppsättningen utan att någon biljett faller bort. Kör routern på `git diff --cached --name-only` före VARJE commit, inte en gång per bunt. (2026-09-12, BIN-1165)
- [Workflow] `git add -A && git commit` stagear INGENTING när en grind nekar — grinden är en PreToolUse-hook på hela Bash-anropet, så `git add` kör aldrig. Stagea i ett eget anrop och verifiera med `git diff --name-only` (tomt = index matchar träd). (2026-09-13)
- [Workflow] En granskares domrad spelas in bara om den är sista PLAINTEXT-raden — domhalvan av commit-grinden är en `SubagentStop`-hook som läser `last_assistant_message`. Lägg kravet ÖVERST i varje dispatch, och verifiera i loggen på granskarens eget id — fältet är `"t":"verdict"`. Två fullgoda granskningar av BIN-1117 kastades bort så 2026-09-16. Redigera aldrig pluginet och skriv aldrig loggen för hand. (2026-09-16)
- [Workflow] Kontrollera granskningsloggen EFTER varje granskarkörning, inte bara när commiten nekas — grinden kräver att SAMMA körning både läste varje skyldig fil vid den stageade shan OCH avslutade på en dom. Greppa loggen på granskarens EGET agent-id när den rapporterar och jämför mot `git rev-parse :<fil>`. (2026-09-16, bunt C)
- [Workflow] En KRYMPANDE union kan dra in en roll som aldrig kritiserat, och den rollen ser precis det krympningen blottade — BIN-1050/1052 skrev regeln för en VIDGAD union, BIN-1122 för ett byte av säte; att TA BORT en fil är den tredje formen. BIN-1131 konvenerade panel, och den krympta unionen routade om. Routa på den union du är på väg att committa, inte på urvalets. (2026-09-16b, BIN-1131)
- [Workflow] En `review`-rad i `events.jsonl` kan VÄNDAS av en senare kritik i samma bunt. Lägg till EN daterad `correction`-rad med commit-shan; redigera aldrig originalraden. Skriv `measured` i en form som kan MOTSÄGA raden — `git show --name-only <sha>` listar filerna. (2026-09-16b, BIN-1131)
- [Workflow] Kartlinterns spärr mot krympande prosa fäller varje strykning — `check-workflow-map.mjs` jämför flödets längd mot `workflow-map-content-baseline.json`. Regenerera baslinjen i samma commit; förväxla den inte med ägarkartans flagga, som gör ett hål permanent. (2026-09-16b, BIN-1202)
- [Workflow] Att ge EN fil ett säte i ägarkartan kan göra dess SYSKON nyupptäckt ägarlösa och stoppa regenereringen mitt i bunten — `--update-gaps` gör hålet permanent och är fel svar. Kör hela sviten efteråt: ägarbaslinjen läses som indata av test i filer bunten inte rör. (2026-09-16, BIN-1206)
- [Workflow] Granskningsloggen är domen, och två av tre granskartyper bokförde ingen dom alls — greppa loggen på granskarens EGET agent-id när den rapporterar, inte när commiten nekas. Att lägga kravet först räcker inte; säg också att sista raden ska vara vanlig assistenttext och inte enbart en hand-back. (2026-09-16, BIN-1195)
- [Workflow] En kritik som gör bunten väsentligt större än urvalet antog ska leda till att biljetten DRAS UT före bygget — kritikens kostnad är redan betald. Att bygga halvt och parkera är sämst: koden kan inte committas och nästa sprint ärver ett halvbyggt träd. Skriv HELA panelen på biljetten, lämna den i Backlog, och säg uttryckligen att ingen kod skrevs. (2026-09-17, BIN-1207/1103)
- [Workflow] En granskares domrad skrivs inte tillförlitligt — läs granskningsloggen på granskarens EGET agent-id efter VARJE körning och bekräfta att en domrad finns bredvid läsraderna. Saknas den står agentens FÖRRA dom kvar, vilket kan vara ett `fail`, och commiten nekas medan rapporten framför dig säger pass. (2026-09-17)
- [Workflow] En kritik som ändrar VAD du bygger ändrar VEM som äger det — routa om efter att ett villkor vikts in, inte bara när filer läggs till eller faller bort. BIN-1205 routade till #8 på `docs/RUNBOOK.md`, så leveransen blev en post i `.claude/rules/accepted-deviations.md`, som ägs av #25. panelen flyttade sig och `check_staged_routing` nekade commiten med #25 som NOT REVIEWED. Fjärde orsaken till panelrörelse vid sidan av vidgad union, krympt union och bytt säte. (2026-09-17)
- [Workflow] En granskare som dödas av en användningsgräns bokför läsningar men ingen dom, och samma tak stoppar varje ny granskare — spara varje bunt som en daterad patch FÖRE sista granskningsvarvet och skriv "byggd, INTE committad, återställbar från <fil>" på biljetten. Kör aldrig grindens granskare på en billigare modell för att komma förbi taket. (2026-09-18)
- [Workflow] En post i en loggfil får bara committas med det träd som gör den sann — ta bort en senare bunts block, committa, och lägg tillbaka det i den senare buntens commit; ingen interaktiv staging behövs. (2026-09-18, BIN-1227/1211)
- [Workflow] Be aldrig en granskare att "inte göra om analysen" för att få en dom bokförd — auto-läget flaggar det som grindkringgång och domen är inget bevis. Kör en fullständig, oberoende granskning av samma bytes med domen som sista vanliga textrad. (2026-09-18, BIN-1237)
- [Workflow] Att SAMMANKALLA en kritik och att BOKFORA den ar tva handlingar, och `check_staged_routing.mjs` laser bara den andra — en kritik som kordes och godkande blockerar commiten tills en rad i `events.jsonl` namner dess roll. Logga nar kritiken svarar. Grindens tva utvagar ar bada giltiga: logga rollen som kritiserade, eller committa splittat sa varje commits union routar till den kritik som kordes. (2026-09-20)
- [Workflow] En biljett ar en gammal ogonblicksbild aven for den halva den sager ar OBYGGD — kor grep-of-main per halva, inte per biljett. `docs/workflow-map.html` ar en oberoende beskrivning av samma kod; motsager den en biljett ar det matbart. BIN-624:s halva 1 var shippad i `6373f6a4` och kroppen sa motsatsen. (2026-09-20)
